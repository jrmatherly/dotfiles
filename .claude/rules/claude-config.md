# Claude Code config in this repo

- **Hooks**: each script's header says what it does and `.claude/settings.json` wires them. `pnpm check` runs all four self-checks.
  - `lint-edited.sh` lints only within `pnpm check`'s scope and exits 2 so Claude sees problems. `lint-bash-edits.sh` feeds it the files in `tool_response.bashEditDiff` (`bashEditDiffEnabled: true` in the tracked user settings turns recording on in every permission mode). That list is best effort: a file another process saved can appear in it, and a command that exits non-zero or runs in the background records nothing, so `pnpm check` before committing stays the gate.
  - `commit-gate.sh` blocks a commit when `pnpm check` fails or the hook crashes or times out (`onFailure: block`). Its `if: Bash(*commit*)` skips the spawn for other commands, so the pattern must match everything the script treats as a commit. It tests the working tree, not the index, and gates only a repo that ships an identical copy of the hook.
  - A hook added to the settings file is picked up only by sessions started after the edit (measured 2026-10-25: the settings doc's live-reload claim did not hold for a new PreToolUse group).
- **Permissions**: running `setup.sh`, `setup/*`, `set-defaults` or `upup` asks first, because they change the machine. The usual invocation forms are covered, but it's a guard, not a hard boundary. In project settings a single leading `/` anchors at the project root (`//` is absolute, `~/` is home). The tracked user settings (`agents/claude-settings.json`) ask before `curl` and `gh api`, deny Read on credential paths and `git add -f`, and allow only the read forms of `gh issue` and `git remote` (writes go past auto mode's classifier otherwise); see `agents/README.md`. `bin/lib/test-conventions` asserts both sets of rules.
- **Global Claude rules**: `tilde/.claude/rules/*.md` are tracked and linked file-by-file into the real dir `~/.claude/rules`; `index.md` lists them. `jstack-models.md` is rewritten through its symlink by `/jstack:setup-jstack`. `chrome-devtools.md` and `handoffs.md` carry learnings for plugins, kept here because edits to a plugin's cached skill are lost on update. `~/.claude/CLAUDE.md` is deliberately not tracked, because `codegraph install` rewrites it via rename, which would break a symlink.
- **Project skills and agents**: `add-tool` (new-tool checklist), `docs-audit` (forks the `docs-auditor` agent) and `validate-setup` (user-only: a before/after snapshot diff around `./setup.sh`, which the user runs in their own terminal, never Claude). `auditor-readonly.sh` applies inside that subagent. It allowlists commands and, for tools whose options can write or run programs, each option by whole name, so neither a denylist gap nor an abbreviated long option gets through. A command that passes is approved with `permissionDecision: allow`, because the forked auditor runs non-interactive and a call auto mode escalated to a prompt was denied with nobody to ask; deny and ask rules still apply.
