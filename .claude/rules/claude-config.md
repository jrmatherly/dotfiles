# Claude Code config in this repo

- **Hooks**: `.claude/settings.json` runs `.claude/hooks/lint-edited.sh` after Edit/Write (and Serena edit tools). It prettier-formats and lints the one edited file, but only within `pnpm check`'s scope (the prettier globs and top-level `bin/*`; `bash -n` + shellcheck only for the files on `bin/lib/check`'s list, which includes `tilde/.claude/*.sh` but not sourced snippets like `colors/*.sh` or the `bin/lib/` helpers other than `test-*`, so those are skipped), exiting 2 so Claude sees problems. Files written through Bash (heredocs, `sed -i`, `tee`) get the same treatment from `lint-bash-edits.sh` (PostToolUse Bash), which reads the changed-file list Claude Code records in `tool_response.bashEditDiff` (`bashEditDiffEnabled: true` in the tracked user settings turns recording on in every permission mode) and feeds each file to `lint-edited.sh`, or asks for `pnpm check` when more than 25 changed. The list is best effort: a file another process saved during the command can appear in it, and a command that exits non-zero or runs in the background records nothing, so `pnpm check` before committing stays the gate. A PreToolUse hook on Bash (`commit-gate.sh`) runs `pnpm check` in the repo a `git commit` targets (the directory of a preceding `cd <dir>` or the commit's own `git -C <dir>`, else the session cwd) and blocks the commit when the check fails or the hook crashes or times out (`onFailure: block`); when setup or mise files are changed without a README it tells Claude so. It tests the working tree, not the index, and gates only a repo that ships an identical copy of the hook (this one or a worktree of it). A hook added to the settings file is picked up only by sessions started after the edit (measured 2026-10-25: the settings doc's live-reload claim did not hold for a new PreToolUse group). `pnpm check` runs all four hook self-checks (`.claude/hooks/test-lint-edited.sh`, `.claude/hooks/test-lint-bash-edits.sh`, `.claude/hooks/test-commit-gate.sh`, `.claude/hooks/test-auditor-readonly.sh`).
- **Permissions** (`.claude/settings.json`): allowed without prompting are `pnpm check`/`pnpm format`, `shellcheck`, `bash -n`, `zsh -n`, `bash vscode/test-vscode-settings.sh` and the hook self-checks. Running `setup.sh`, `setup/*`, `set-defaults` or `upup` asks first (they change the machine). The usual invocation forms are covered (`./`, `bash`/`sh`, absolute path, `bin/`), but it's a guard, not a hard boundary. Edits are denied for `ql-plugins/`, `obsidian/.obsidian/plugins/` and `tilde/.config/gh/hosts.yml`.
- **Global Claude rules**: `tilde/.claude/rules/*.md` are tracked and linked file-by-file into the real dir `~/.claude/rules` (`serena.md` holds Serena's launch invariants and why `trusted_project_path_patterns` stays `[]` in the untracked `~/.serena/serena_config.yml`; `tool-checks.md` says to verify with `command -v` before claiming a CLI is missing; `verify-first.md` is the never-assume/always-verify working rule; `jstack-models.md` sets the model and reasoning effort per jstack role as `model effort` lines and is rewritten through its symlink by `/jstack:setup-jstack`; `chrome-devtools.md` and `handoffs.md` carry learnings for the chrome-devtools MCP and the `remember` plugin, kept here because edits to a plugin's cached skill are lost on update; `hindsight.md` says how this machine's Hindsight memory differs from the vendor defaults and how to credit and correct recalled memory; `index.md` lists them). `~/.claude/CLAUDE.md` is deliberately NOT tracked, because `codegraph install` rewrites it via rename (which would break a symlink).
- **Claude catalog**: `bin/claude-catalog` builds `~/.claude/catalog/{CATALOG.md,CATALOG-lite.md,catalog.html}` (installed skills, commands, subagents, MCP servers) via `agents/catalog/build_catalog.py`, run through mise's Python 3.11+ (`tomllib`; system python3 is 3.9). Hand-edited notes live in `agents/catalog/curated.toml` (the script exits 1 if it names something not installed, except an `[mcp.*]` server, which only warns, in a group's `items` too: MCP registration is per machine); `catalog_template.html` is the HTML shell. The tracked global rule `tilde/.claude/rules/catalog.md` points Claude at the catalog. `__pycache__/` is gitignored.
- **Claude config**: `bin/claude-config save` snapshots into tracked files: `agents/claude-plugins.txt` (`save` never shrinks a tracked file: a missing source warns and keeps it, writes via `.tmp` + `mv`; marketplaces + user-scope plugins, `disabled` flag), `agents/claude-settings.json` (`~/.claude/settings.json` minus tool-owned keys `enabledPlugins`/`extraKnownMarketplaces`/`hooks`, `$HOME` written as `~` only where it starts a path, `//$HOME/` as `~/`, permission lists sorted; credential helpers `apiKeyHelper`/`awsCredentialExport`/`awsAuthRefresh`/`otelHeadersHelper` never saved, and of `env` only `CLAUDE_CODE_*` (except the two the LLM Router's gateway profile writes, `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` and `CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT`: the router adds them whenever a provider exists and never removes them from a real settings file, and `restore` never deletes a key, so tracking them would hand a gateway profile to a Mac with no router), `DISABLE_*`, `MAX_*`, `AZURE_MCP_COLLECT_TELEMETRY`, `HINDSIGHT_API_LLM_PROVIDER` and the `HINDSIGHT_API_*LLM_MODEL` pins, never an API key) and `agents/claude-skills.txt` (`skill <name> <source> <agents>` from `~/.agents/.skill-lock.json`). `restore [plugins|settings|skills] [--dry-run]` re-applies them: missing marketplaces/plugins, settings merged with existing values winning and permission lists unioned (no rewrite if nothing is missing), and `npx skills add` for skills missing on some agents (stdin from `/dev/null`; an invalid settings merge warns instead of aborting). `restore skills --update` reinstalls every tracked skill for its listed agents instead (the CLI's own `skills update` reinstalls with no agent list, so a skill tracked for one agent would spread to all). Wired into `setup/misc.sh` (restore, then `claude-catalog`; the `jrmatherly/skills` marketplace and skills are public, so no credential is needed) and `bin/upup` (`restore skills --update`, `claude-config save`, then catalog; a failure in either is a `fail` line and doesn't abort upup). `zsh/env.zsh` exports `DO_NOT_TRACK=1` (also used by the skills CLI and the Sentry CLI from the `getsentry/tools` Brewfile tap; see `docs/privacy.md`).
- **Hindsight memory wiring**: `bin/hindsight-memory` wraps the vendor installer `@vectorize-io/hindsight-coding-agents` (version pinned in the script, next to the `hindsight-embed` pin) for opt-in, per-repo long-term memory in Claude Code and Codex. `init` (from `setup/misc.sh`) runs the installer only when `~/.hindsight/coding-agent.json` is missing, and merges the repo's defaults into that file additively (existing keys win; the file is never tracked). `upgrade` (from `upup`) re-runs the pinned installer and reports a newer npm release as a notice. `paths`, `on|off`, `survey`, `status` and `uninstall` manage it. The extraction provider is pinned where the hooks read it: `HINDSIGHT_API_LLM_PROVIDER=claude-code` in `tilde/.zshenv` (terminals, and Codex started from one) and in `env` of `agents/claude-settings.json` (app-launched Claude Code), since the daemon starter re-detects it from the hook's environment and rewrites the profile on every cold start. The models are pinned the same way: `HINDSIGHT_API_LLM_MODEL=claude-sonnet-5-5` for reflect and the knowledge-page refresh, `HINDSIGHT_API_RETAIN_LLM_MODEL` and `HINDSIGHT_API_CONSOLIDATION_LLM_MODEL` at `claude-haiku-5-5` for extraction and consolidation, because the provider's own default (`claude-sonnet-4-5-20250929`) retires on 2026-11-30 and the daemon starter forwards every `HINDSIGHT_API_*` variable from the hook's environment. How it behaves at runtime (page injection, the refresh schedule, the `cargo` preflight) is in the global rule `tilde/.claude/rules/hindsight.md`. Design, privacy and the measured costs: `docs/superpowers/specs/completed/2026-10-24-hindsight-memory.md`.
- **Project skills and agents**: `.claude/skills/` has `add-tool` (new-tool checklist), `docs-audit` (forks the `.claude/agents/docs-auditor.md` agent, which never edits but runs only allowlisted read-only commands, enforced by a PreToolUse hook that applies inside that subagent (`auditor-readonly.sh`: a command allowlist plus, for the tools whose options can write or run programs, a per-tool allowlist of option letters and whole long-option names, so neither a denylist gap nor an abbreviated long option gets through; `sed` is excluded because its script can write), and fetches vendor docs; its default scope is the READMEs, `docs/` minus `docs/superpowers/`, and the agent instructions: every `CLAUDE.md`, `agents/instructions.md`, the rules, skills, agents and Serena memories) and `validate-setup` (user-only: before/after snapshot diff around `./setup.sh`, which the user runs in their own terminal, never Claude).
