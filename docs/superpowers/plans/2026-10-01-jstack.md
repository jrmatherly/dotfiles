# jstack Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fork Lauren Tan's `pstack` Cursor plugin into the private `jrmatherly/skills` repo as `jstack` (router skill `j-mode`), ported to Claude Code, installable as a private Claude Code plugin marketplace that `./setup.sh` bootstraps, and re-syncable from upstream. Also: a re-runnable VS Code font picker, and the 2026-10-01 setup-run follow-ups.

**Architecture:** `jrmatherly/skills` gains a generated plugin at `plugins/jstack/`. It is never hand-edited: `scripts/sync-jstack` fetches upstream `cursor/plugins` at a pinned commit, copies the kept parts, applies an ordered substitution table (renames + mechanical Cursor→Claude Code translations), applies `jstack/patches/*.patch` (semantic ports), regenerates `bun.lock`, and gates on `scripts/check-jstack` plus upstream's own Bun tests. The repo root becomes a Claude Code marketplace whose `jstack` entry points at `./plugins/jstack`; dotfiles' `agents/claude-plugins.txt` makes `claude-config restore` install it.

**Tech Stack:** bash, perl (literal substitution), minijinja-cli (VS Code settings template), `git apply`, Bun (mise), Claude Code plugins (skills + agents), Skills CLI 1.7.0, dotfiles setup scripts.

**Spec:** this conversation's decisions (2026-10-01), recorded under Global Constraints. Review of v1 of this plan: see "Revision log" at the end.

- [ ] **Step 2:** `scripts/sync-jstack`

```bash
#!/bin/bash
# Regenerate plugins/jstack from upstream pstack: fetch the pinned commit,
# keep skills/agents/LICENSE, rename, substitute, patch, relock, check, test.
# Never edit plugins/jstack by hand: change jstack/substitutions.tsv or
# jstack/patches instead.
set -euo pipefail

root="$(cd "$(dirname "$0")/.." && pwd -P)"
out="$root/plugins/jstack"
apply_patches=true
while [ $# -gt 0 ]; do
  case $1 in
    --no-patches) apply_patches=false ;;
    --out) out="$2"; shift ;;
    *) echo "usage: sync-jstack [--no-patches] [--out DIR]" >&2; exit 2 ;;
  esac
  shift
done

die() { echo "sync-jstack: $*" >&2; exit 1; }
command -v bun > /dev/null || die "bun: not found (mise install bun)"

repo=$(sed -n 's/^repo=//p' "$root/jstack/upstream")
path=$(sed -n 's/^path=//p' "$root/jstack/upstream")
commit=$(sed -n 's/^commit=//p' "$root/jstack/upstream")
work="$(mktemp -d)"
trap 'rm -rf "$work"' EXIT

git clone -q --filter=blob:none --no-checkout "$repo" "$work/src" || die "fetch: clone failed"
git -C "$work/src" sparse-checkout set "$path"
git -C "$work/src" checkout -q "$commit" || die "fetch: commit $commit not found"
src="$work/src/$path"

stage="$work/jstack"
mkdir -p "$stage/.claude-plugin"
cp -R "$src/skills" "$src/agents" "$src/LICENSE" "$stage/"
mv "$stage/skills/poteto-mode" "$stage/skills/j-mode"
mv "$stage/skills/setup-pstack" "$stage/skills/setup-jstack"
mv "$stage/agents/poteto-agent.md" "$stage/agents/j-agent.md"

# Literal substitutions, in file order, over text files (bun.lock is
# regenerated below; LICENSE keeps the upstream notice verbatim)
while IFS=$'\t' read -r from to; do
  if [ -z "$from" ] || [ "${from:0:1}" = "#" ]; then continue; fi
  { grep -rlF --exclude=bun.lock --exclude=LICENSE -- "$from" "$stage" || true; } \
    | while read -r f; do
      FROM="$from" TO="$to" perl -pi -e 's/\Q$ENV{FROM}\E/$ENV{TO}/g' "$f"
    done
done < "$root/jstack/substitutions.tsv"

if [ "$apply_patches" = true ]; then
  git -C "$stage" init -q # git apply resolves paths against a repo
  for p in "$root"/jstack/patches/*.patch; do
    [ -e "$p" ] || continue
    git -C "$stage" apply --whitespace=nowarn "$p" || die "patch: ${p##*/} no longer applies"
  done
  rm -rf "$stage/.git"
fi

# Version omitted on purpose: Claude Code then tracks this repo's commits
# instead of pinning installs to a version string. No skills/agents keys: the
# default skills/ and agents/ dirs are scanned, and "agents" accepts only .md
# files (a directory fails validation)
cat > "$stage/.claude-plugin/plugin.json" << 'JSON'
{
  "name": "jstack",
  "description": "Jason's agent workflows: j-mode router, design and review panels, verification, principles. Fork of pstack by Lauren Tan (MIT).",
  "author": { "name": "Jason Matherly" },
  "license": "MIT"
}
JSON

scripts="$stage/skills/j-mode/scripts"
(cd "$scripts" && bun install --lockfile-only > /dev/null) || die "relock: bun install --lockfile-only failed"
# JSTACK_NO_CHECK=1: patch-authoring escape hatch (README, "Patch workflow")
if [ "${JSTACK_NO_CHECK:-}" != 1 ]; then
  "$root/scripts/check-jstack" "$stage" || die "check: see above"
fi
if [ "$apply_patches" = true ] && [ "${JSTACK_NO_CHECK:-}" != 1 ]; then
  (cd "$scripts" && bun install --frozen-lockfile > /dev/null && bun test orch watch-pr > /dev/null) \
    || die "test: bun test failed in skills/j-mode/scripts"
  rm -rf "$scripts/node_modules"
fi

rm -rf "$out" && mkdir -p "$(dirname "$out")" && mv "$stage" "$out"
echo "sync-jstack: $out from $repo@$commit"
```

### Task 2: Substitution table + strict checker

- [ ] **Step 1:** Write the checker first

```bash
#!/bin/bash
# Validate a generated jstack tree (default plugins/jstack): no upstream names
# or Cursor-only references, valid frontmatter, live links, and every skill a
# skill names actually exists (most are disable-model-invocation, so a dangling
# name can't fall back to the Skill tool).
set -uo pipefail
dir="${1:-$(cd "$(dirname "$0")/.." && pwd -P)/plugins/jstack}"
fail=0
bad() { echo "$*" >&2; fail=1; }

forbidden='poteto|pstack|lauren|~/\.cursor|\.cursor/|\bCursor\b|AskQuestion\b|generalPurpose|cursor-team-kit|\bdeslop\b|control-ui|control-cli|\bcreate-skill\b|agent-transcripts|environment: "cloud"|\bGrok\b|gpt-5\.|claude-opus-[0-9-]+-(max|xhigh|high|medium)|\.mdc\b|is_background|\bTask tool\b|^mode: true|^icon:|^reminder:'
while IFS= read -r hit; do bad "$hit: upstream/Cursor reference"; done \
  < <(grep -rnEI --exclude=LICENSE --exclude=bun.lock "$forbidden" "$dir")

for f in "$dir"/skills/*/SKILL.md; do
  d="$(basename "$(dirname "$f")")"
  name="$(awk 'NR>1 && /^---$/{exit} /^name: /{sub(/^name: */,""); print; exit}' "$f")"
  [ "$name" = "$d" ] || bad "$f: name '$name' != directory '$d'"
  grep -q '^description: ' "$f" || bad "$f: no description"
done

while IFS=: read -r f _ m; do
  t="${m#*(}"; t="${t%)}"
  case $t in */* | *.*) ;; *) continue ;; esac # placeholders like (url) in prompt templates
  [ -e "$(dirname "$f")/$t" ] || bad "$f: broken link $t"
done < <(grep -rnoE --include='*.md' '\]\([^):#]+\)' "$dir")

# **name** / `name` references to skills must exist
skills=$(ls "$dir/skills")
while IFS=: read -r f _ ref; do
  ref="${ref//[\*\`]/}"
  grep -qx "$ref" <<< "$skills" || bad "$f: references missing skill '$ref'"
done < <(grep -rnoE --include='*.md' '\*\*(principle-[a-z-]+|how|why|architect|arena|swarm|interrogate|unslop|technical-writing|no-comments|show-me-your-work|tdd|recall|reflect|teach|figure-it-out|blast-radius)\*\*' "$dir")

grep -q 'Copyright (c) 2026 Lauren Tan' "$dir/LICENSE" || bad "LICENSE: upstream notice missing"
claude plugin validate "$dir" > /dev/null 2>&1 || bad "claude plugin validate $dir failed"
exit $fail
```

### Patch authoring workflow (Tasks 3–6)

`sync-jstack` deletes its stage on failure, so author patches from a base tree built the same way:

```bash
base=$(mktemp -d)/jstack-base
JSTACK_NO_CHECK=1 scripts/sync-jstack --no-patches --out "$base"
cp -R "$base" "${base%-base}-edit"
# …edit files under …/jstack-edit…
(cd "$(dirname "$base")" && git diff --no-index jstack-base jstack-edit) \
  | sed -E 's#^(---|\+\+\+) (a|b)/jstack-(base|edit)/#\1 \2/#; s#^diff --git a/jstack-base/(.*) b/jstack-edit/#diff --git a/\1 b/#' \
  > jstack/patches/NN-area.patch
```

(`sed -E`: macOS sed ignores `\|` in basic regexes — verified.) Patch N is authored against base + patches `< N` (temporarily move later patches aside). One area per patch, so an upstream change breaks one patch.

### Task 9: Templated VS Code settings with minijinja (dotfiles)

**Tool decision (researched 2026-10-01, validated hands-on):** `minijinja-cli` 2.24.0 (homebrew-core; Rust single binary; Jinja2 syntax; maintained by Jinja's original author, release 2026-08-12).

| Candidate | Verdict |
|---|---|
| **minijinja-cli** | **Chosen.** Reads TOML/YAML/JSON data files, `--strict` errors on undefined values with the template line, `--env` exposes `HOME`, auto-escapes values as JSON for `*.json.j2` (a font name with `"` or `\` can't break the file), keeps comments and the trailing newline. | gomplate 5.2.0 | Capable, but Go-template syntax; no advantage here. |
| envsubst (installed) | Clobbers VS Code's own `${version}` / `${file}` (settings.json:391, :505); no conditionals or data files. |
| jsonnet, cue (cue installed) | Emit plain JSON: lose the file's explanatory comments. |
| chezmoi 2.73.0 | Solves app-rewrites-config drift properly, but means replacing this repo's symlink model; out of scope. |
