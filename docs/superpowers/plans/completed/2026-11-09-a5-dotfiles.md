# A5 Dotfiles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `mise dotfiles apply` links and copies everything `setup/symlinks.sh` did, the script is deleted, and the settings UI shows the link state and can apply it.

**Architecture:** `tilde/.config/mise/conf.d/40-dotfiles.toml` declares 38 `[dotfiles]` entries. `setup/dotfiles-extras.sh` does the five things mise cannot express (git identity, a public-key warning, two `/usr/local/bin` links, Firefox hard links, bat's cache). The `dotfile` adapter reads `mise dotfiles status --json` as one read-only status setting and runs `mise dotfiles apply --yes` for `dotfiles-settings apply dotfile`.

**Tech Stack:** mise 2026.11.5 `[dotfiles]`, bash, Python 3.11 standard library.

**Spec:** `docs/superpowers/specs/2026-11-09-mise-first-setup-and-settings-ui.md`, phase "A5. Dotfiles".

## Global Constraints

- Minimum mise version: 2026.11.5.
- Tests that isolate mise set `MISE_CONFIG_DIR` only. Never set `MISE_GLOBAL_CONFIG_FILE`.
- No command in this plan, and no code it adds, passes `--force` or `-f` to `mise dotfiles apply`.
- The adapter imports nothing outside the standard library.
- Bash scripts start with `#!/bin/bash` and a header comment, define their output helpers inline, and pass `pnpm check`.
- Commit subjects are short, imperative, sentence case, with no prefix. Every task ends with `pnpm check` passing.
- Docs change in the same commit as the behaviour they describe.
- Line numbers in this plan are from commit `9af6244`. An earlier phase (A1 to A4) may have moved them, so find the quoted text with `grep -n` before editing.
- Commits name their paths. No `git add -A`, no `git add .`, no bare directory. The working tree holds an unrelated uncommitted change to `agents/claude-settings.json` that must never enter a commit of this plan.
- A step that changes this Mac says so in its title and needs the user's explicit go-ahead in chat. `./setup.sh` is interactive and the user runs it. No test and no step applies against the real HOME without that go-ahead.
- The phase gate is `pnpm check`, which runs `bin/lib/test-dotfiles` and `setup/tests/dotfiles-extras.sh`. `mise dotfiles status --missing` on the real HOME is the expected result of the user's run and is reported. `mise bootstrap status --missing` is informational and no step requires it to exit 0.
- `setup/dotfiles-extras.sh` is committed with mode 755. `bin/lib/test-conventions` checks that tracked `setup/*.sh` files are executable (A3 adds the check, this plan relies on it). The script's own test runs `bash "$script"` and cannot see a missing mode bit.

## Review Focus

1. **A real file or folder already sits at a target** (a new Mac with its own `~/.zshrc`). Expected: apply exits 1, names every such path, and writes nothing. Pinned by `test-dotfiles`.
2. **`~/dotfiles` is missing or is not this clone.** Every source goes through it. Expected: `setup.sh` stops before the apply, and mise alone fails with `sources do not exist` and writes nothing. Pinned by `test-dotfiles` and the guard in Task 3.
3. **A new file under `tilde/` with no entry.** Expected: `pnpm check` fails and names it. Pinned by the coverage loop in `test-dotfiles`.
4. **A Mac with `mole/whitelist.local`.** A plain apply repoints its link to the shared list without asking. Expected: an entry in `config.local.toml` keeps the local list. Pinned by `test-dotfiles`. This Mac is that case (see Measured facts).
5. **A Mac's live `~/.codex/config.toml` differs from the tracked one** (its own model, MCP entries with tokens, a missing key, or broken TOML). Expected: values and keys the Mac has are kept, only missing keys are added, a second apply changes nothing, and an invalid file is reported with exit 1 and left byte-identical. Pinned by `test-dotfiles` (E9, E18).
6. **A pull changes a tracked Firefox file.** Git writes a new inode, so the hard link breaks and the profile holds the old text. Expected: the next run moves the stale copy to a free `.backup` name and links again. Pinned by `setup/tests/dotfiles-extras.sh`.

## Decisions the spec left open

- **Sources are written `~/dotfiles/…`.** E1 to E4. `~/dotfiles` must be the clone before any apply. Task 3 adds the guard to `setup.sh`.
- **Relative sources are not used: `~/dotfiles` is required.** Settled by the owner (spec Decisions, item 8). The 38 entries stay as written. The record below is why the alternative was not taken. The review measured that a source written relative to the config file (`"../../../.ackrc"` in `conf.d/40-dotfiles.toml`, read through the `~/.config/mise` symlink) applied and read back correctly in a scratch HOME, with the link target `~/.config/mise/conf.d/../../../.ackrc`. A switch would cost three things. Every link would resolve through `~/.config/mise`, so that one link becomes the single point every other link depends on, as `~/dotfiles` is today. The `~/.config/mise` entry could report the link but its repair is unmeasured (E1). `bin/lib/test-dotfiles` copies the fragment into a plain config dir, so it would have to link the config dir into the repo instead. The builder does not switch.
- **`tilde/` is not one `symlink-each` entry.** E5. The spec says "`tilde/` maps with `symlink-each`". Each top-level file is its own `symlink` entry, and only `~/.claude/rules` is walked. `test-dotfiles` fails when a file in `tilde/` has no entry.
- **The two `/usr/local/bin` links are a step in `setup/dotfiles-extras.sh`, not `[bootstrap.files]`.** E13 and E14. The spec is wrong on this point. A copy would not work either: VS Code's `code` script finds the app from its own location.
- **Mole's `.local` preference is an entry in `config.local.toml`.** E12. `variants` select by OS or profile, not by whether a file exists. A1 gitignores `config.local.toml`.
- **`~/.config/mise` is declared, and `setup.sh` still creates it.** mise reads the fragment through that link, so the entry cannot create it on a new Mac. It reports it and repairs a link that points elsewhere.
- **No `[tasks.bootstrap]` and no hook, in this phase or later.** `setup.sh` runs `setup/dotfiles-extras.sh` itself, after `mise dotfiles apply --yes` in this phase and after `mise bootstrap` once A6 lands. The script is never a `pre-dotfiles` or `post-dotfiles` hook. mise runs those hooks on every `mise dotfiles apply` (`mise dot apply --help` says so, and a scratch run with a `post-dotfiles` hook printed its output after a plain apply). That includes the apply started by `dotfiles-settings apply dotfile` from the settings UI, where the script's sudo prompt and git identity prompt cannot be answered. A6 owns the task table. Measured by A6: a second `[tasks.bootstrap]` in another fragment is silently replaced.
- **Firefox: a different file is moved to a free `.backup` name, then linked.** No prompt. The old script asked skip, overwrite or backup.
- **The `DOTFILES_GIT_*` knobs stay.** They move with the prompt into the extras script. The spec's "delete … the knobs' prompt path" is read as: delete it from `symlinks.sh`. A2 agrees: it leaves the four out of the registry and says A5 keeps them.
- **The four knobs are not registry entries.** They are read once, only while `~/.gitconfig.local` is missing. After that the identity lives in that file, so a registry row would show a value with no effect, and `source` and `seed` would mean nothing for it.
- **The Codex config is a `merge = "missing"` edit at `0600`, and the "lacks these lines" warning is dropped** (spec Decisions, item 6; E9, E18). A missing file is created at `600`. Later applies add only the keys the live file lacks, and a value the Mac changed is kept, so the warning has nothing left to report. The file is never linked because setup's own `codex mcp add` (`setup/misc.sh`, SnippetsLab), Hindsight's installer (`hindsight-memory` wires the `codex` harness) and Codex itself write it on any Mac, and MCP entries can carry tokens. NotchBar and Jean are not the reason: they are two apps on this Mac. Known limits, stated in the fragment's comment: the source's comments are not carried into the target; a key deleted from the live file on purpose returns on the next apply (delete it from the tracked file too); `permissions` applies only on creation, so an existing file keeps its mode; a symlink at the target is replaced by a regular file at 644 when it points at the source and stops the apply when it points elsewhere, so Part B's "remove the link first" step stays; an invalid live file stops the apply with exit 1 and is never rewritten.
- **The tracked `[features] codex_hooks = true  # notchbar-agents-managed-codex-hooks` line is deleted** (spec Decisions, item 6). NotchBar wrote it into a live file that got committed. `codex doctor` (Codex 0.167.0, run from `~`) reports `legacy alias             codex_hooks -> hooks` with the line, and with an empty scratch `CODEX_HOME` lists `hooks` among the enabled flags with `0 overridden`, so it is on by default. A Mac whose live file has the line keeps it: `merge = "missing"` never removes a key.
- **No `ask` permission rule in this plan.** The rules for `mise dot *apply*` are added by A7 in the last phase (spec Decisions, item 7). Until then the owner's go-ahead in chat guards the command.
- **`merge = true` does not replace any part of `claude-config restore`.** Restore lets the machine's value win (`$base * $cur` in `bin/claude-config`), unions the permission arrays, and drops retired rules. `merge = true` makes the source win and replaces arrays whole, so it would delete permissions granted on the Mac. Spec D4 also keeps tool-owned files behind their CLIs.
- **The registry holds one read-only setting, `dotfiles.links`, not one per file.** A link has no value to set or reset. A setting per entry would be a second list to keep paired with the fragment. The status value names every entry that is not applied.

## Part B hook: what `migrate/legacy-to-mise --step dotfiles` needs

1. **Recognise old links.** An old link is a symlink whose `readlink` starts with the clone's physical path. For every entry they read `applied` (E4). Nothing to move.
2. **Find what is in the way.** Run `mise dotfiles apply --dry-run` from `$HOME`. Exit 1 with `refusing to overwrite existing files (use --force):` means conflicts. Each following line that starts with two spaces is one path. Back up each path into `~/.dotfiles-migration-backup/<timestamp>/`, then apply.
3. **Mole.** Before the apply, for each of `whitelist` and `whitelist_optimize` whose `mole/<name>.local` exists, add under `[dotfiles]` in `tilde/.config/mise/config.local.toml`: `"~/.config/mole/<name>" = { source = "~/dotfiles/mole/<name>.local", mode = "symlink" }`. Without it the link is repointed to the shared file (E17).
4. **Codex.** When `~/.codex/config.toml` is a symlink, remove the link before the apply. mise then creates it at `0600` (E9). Without this step mise replaces a link to the clone with a regular file at 644, and a link elsewhere stops the apply with exit 1 (E18).

### Task 4: The `dotfile` adapter

**Files:**

- Create: `settings/src/dotfiles_settings/adapters/dotfile.py`, `settings/tests/test_dotfile.py`
- Modify: `settings/src/dotfiles_settings/adapters/__init__.py`, `settings/src/dotfiles_settings/registry.py`, `settings/registry.toml`, `settings/README.md`, `bin/lib/check`

**Interfaces:**

- Consumes (A2): `model.Setting`, `model.Value`, `model.Source`, `model.SettingsError`, `mise.run_mise`, `ADAPTERS`, `registry.KINDS`, the optional `apply(self, settings: list[Setting]) -> list[str]`, the `DOTFILES_SETTINGS_MISE` variable.
- Produces:

```python
FORCE_HINT = "Move each aside, or adopt it with `mise dotfiles add <path>`, then apply again."

def entries() -> list[dict]            # files + edits of `mise dotfiles status --json`
def label(entry: dict) -> str          # entry["target"], or f'{entry["path"]} ({entry["edit"]})' for an edit
def conflicts(stderr: str) -> list[str]  # the paths mise refused to overwrite

class DotfileAdapter:
    def read(self, s: Setting) -> Value
    def write(self, s: Setting, value: str) -> None   # always raises SettingsError
    def reset(self, s: Setting) -> None               # always raises SettingsError
    def apply(self, settings: list[Setting]) -> list[str]
```

`ADAPTERS["dotfile"] = DotfileAdapter()`. `"dotfile"` is appended to `registry.KINDS`.

Rules:

- `entries()` runs `mise.run_mise(["dotfiles", "status", "--json"])` and returns `data["files"] + data["edits"]`.
- `read`: an entry is fine when its `state` is `applied` or `tracked`. With all fine, `value` is `"<n> of <n> applied"`. Otherwise `value` is `"<fine> of <n> applied"` followed by one `"; <label>: <state>"` per other entry, with `" (<reason>)"` when the entry has a `reason`. `source` is `Source.SEED` (the tracked fragment declares the state, and there is no override tier). `seed` is `None`. `drift` is `True` when any entry is not fine.
- `write` and `reset` raise `SettingsError("dotfiles are declared in conf.d/40-dotfiles.toml, edit that file")`. The CLI rejects a `ro` setting first, so this only guards a wrong registry entry.
- `apply` runs `[os.environ.get("DOTFILES_SETTINGS_MISE", "mise"), "dotfiles", "apply", "--yes"]` with `subprocess.run(..., cwd=Path.home(), capture_output=True, text=True)`. It does not use `run_mise`, because it needs stderr and the exit status. The argument list is a constant: no caller can add `--force`. The apply also runs any `pre-dotfiles` and `post-dotfiles` hook. This plan defines none and `setup/dotfiles-extras.sh` is never one (see Decisions), so nothing here waits on a terminal. `apply dotfile` therefore makes links and copies only. The git identity, the `cot` and `code` links and the Firefox hard links need `setup/dotfiles-extras.sh`.
  - Exit 0: return the non-empty lines of stdout and stderr, each with a leading `mise ` removed.
  - Exit not 0 and `conflicts(stderr)` not empty: raise `SettingsError(f"{n} path(s) in the way, nothing was changed: {', '.join(paths)}. {FORCE_HINT}")`.
  - Any other failure: raise `SettingsError` with the stderr lines that start with `mise ERROR`, minus the `Version:` and `Run with --verbose` lines, each followed by the two-space-indented lines under it. The indented lines name the entry, as in an invalid Codex config (E18).
- `conflicts`: find the line that contains `refusing to overwrite existing files`. Return the lines after it that start with two spaces, stripped, up to the first line that does not.

Registry entry, appended to `settings/registry.toml`:

```toml
[[setting]]
id = "dotfiles.links"
section = "Dotfiles"
label = "Links and copies in the home folder"
help = "What mise dotfiles status reports for conf.d/40-dotfiles.toml. Run dotfiles-settings apply dotfile to create what is missing. A real file in the way stops the apply and nothing is replaced."
kind = "dotfile"
key = "all"
type = "string"
default = ""
access = "ro"
```

`key` is unused by this adapter. `"all"` keeps the field non-empty. The entry carries every required field (`id`, `section`, `label`, `help`, `kind`, `key`, `type`, `access`). `true_value`, `choices` and `widget` are optional in A2's loader and are left out. Nothing more is needed. The help text stays true with no hook: `apply dotfile` creates the missing links and copies, which is all the status counts.
