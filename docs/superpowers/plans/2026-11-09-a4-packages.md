# A4 Packages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every formula, cask and VS Code extension this repo installs is declared in mise's config and installed, upgraded and reported by mise, and nothing in setup, `upup` or shell startup calls `brew`.

**Architecture:** `tilde/.config/mise/conf.d/30-packages.toml` replaces `setup/Brewfile`. Seven tap formulae move to `[tools]`. An in-repo package-manager plugin at `mise-plugins/vscode/` installs the extensions. `setup/packages.sh` replaces `setup/brew.sh`: it installs mise with mise's own installer, links the plugin and applies the packages. Shell startup gets static lines in place of `brew shellenv`. `upup` upgrades through `mise bootstrap packages upgrade`. The settings package gains a read-only `package` adapter with one entry per manager.

**Tech Stack:** mise 2026.11.5 (`bootstrap packages`, package-manager plugins in Lua), bash 3.2, zsh 5.9, Python 3.11+ standard library, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-09-mise-first-setup-and-settings-ui.md`, phase "A4. Packages", decisions D5, D6, D11, D12. Read it first.

## Global Constraints

- Minimum mise version: 2026.11.5.
- The new method is Homebrew-free. Setup, `upup` and shell startup never call `brew` (D5).
- Part A never reads the old layout and carries no compatibility code for it. What only an early adopter needs goes in [Handoff to Part B](#handoff-to-part-b).
- The package's core imports nothing outside the standard library. Its tests run with plain `python3`.
- Shell startup must not run an interpreter or mise unless a cached file is stale.
- Bash scripts start with `#!/bin/bash` and a header comment, define their output helpers inline, and pass `pnpm check`.
- Commit subjects are short, imperative, sentence case, with no conventional-commit prefix.
- GitHub Actions are pinned to a commit SHA with the version in a comment, as in `check.yml`.
- Every phase updates the docs that describe what it changed, in the same commit (D12).
- Tests that isolate mise set `MISE_CONFIG_DIR`, `MISE_DATA_DIR`, `MISE_STATE_DIR` and `MISE_CACHE_DIR`. Never set `MISE_GLOBAL_CONFIG_FILE`.
- **Never run these without the user's explicit go-ahead in chat:** `mise bootstrap packages apply`, `upgrade` or `prune` without `--dry-run`, `mise self-update`, `mise install`, `./setup.sh`, `upup`, any `brew` command that changes state. Each step that changes the machine says so and waits for a yes. Tasks 5 and 6 are the only places a real package apply runs.
- Line numbers are from commit `9af6244`, before A1 to A3. Find each quoted line with `grep -n` before editing it.

`managed_by` appears on casks only (`"homebrew"`, `"mise"` or `"unknown"`). `auto_updates` appears only when true. Formulae carry neither. States seen: `installed`, `missing`, `needs_repair` (JSON uses an underscore, the table prints "needs repair"). `status --missing` exits 1 on any other state. With 184 packages the command took 0.7 s.

**Config keys.** `[bootstrap.brew] adopt` and `homebrew_metadata` parse. An unknown key under `[bootstrap.brew]` is a warning. `"brew:trash-cli" = { version = "latest", link = true }` is `mise::config::parse_error`. A plugin key such as `"vscode:golang.go"` needs the plugin linked, or the manager shows as unavailable.

**`brew shellenv zsh` prints exactly:** `HOMEBREW_PREFIX`, `HOMEBREW_CELLAR`, `HOMEBREW_REPOSITORY` (all `/opt/homebrew` based), `fpath[1,0]="/opt/homebrew/share/zsh/site-functions"` with `export FPATH`, `PATH="/opt/homebrew/bin:/opt/homebrew/sbin:$PATH"`, a `MANPATH` line that only reformats an already-set `MANPATH`, and `INFOPATH="/opt/homebrew/share/info:${INFOPATH:-}"`. In this repo only `HOMEBREW_PREFIX` is read (`zsh/init.zsh:8`, `bin/upup:471`, `bin/ca-roots:40`, `bin/lib/test-shell:121`).

**The rustup repair.** `status` reports `rustup` as `needs_repair`, and a dry-run apply prints `repair rustup/1.29.3: linked-keg record`. From mise's source at tag `v2026.11.5` (`crates/mise-system-packages/src/brew/pour.rs`, `pending_record_repair` and `repair_link_record`): when a formula's `opt` link is valid, its keg has no `.mise-keg-only` marker file, `var/homebrew/linked/<name>` is absent, and some file under the prefix's `bin`, `lib` and similar dirs links into the keg, mise creates the one symlink `/opt/homebrew/var/homebrew/linked/rustup -> ../../../Cellar/rustup/1.29.3`. It does not relink the keg (the unit test is named `test_repairs_active_records_without_relinking_the_keg`). The trigger here is `/opt/homebrew/bin/rustup`, which the formula's own post-install step links (`post_install_steps` in `https://formulae.brew.sh/api/formula/rustup.json`). Homebrew poured the keg, so the marker is missing and mise mistakes a keg-only formula for a linked one. Task 5 confirms this by diff before anything else is applied.

## Decisions this plan makes

| # | Decision | Why |
| --- | --- | --- |
| P1 | `30-packages.toml` is generated once by a script the implementer writes in the scratchpad and never commits. | 367 entries with comments. A one-off script is checked by counts. Hand-copying is not. |
| P2 | `[bootstrap.brew] adopt = true`. `homebrew_metadata` is not set. | `adopt` keeps an app that is already in `/Applications` instead of replacing it (replacing drops privacy permissions), and fails without touching it when it is a different build. `homebrew_metadata = true` hands each cask to Homebrew and makes mise skip it in apply, upgrade and prune, which is the opposite of D5. |
| P3 | No version pins and no `link`. `test-packages` rejects any value but `"latest"`. | mise cannot install an old bottle or cask. A pinned entry is skipped with a warning forever. |
| P4 | `brew "mise"` is dropped. mise comes from `https://mise.run` into `~/.local/bin/mise`. `upup` runs `mise self-update --yes`. | The spec. A formula entry would need mise to install mise. |
| P5 | `bin/brewpick` is deleted with no replacement script. | A subset install is `mise bootstrap packages apply brew:<name>`. The settings UI shows what is missing and `apply package` installs it. The `manual "MonoLisa"` entry was a link opener; `fonts/README.md` already has the link. |
| P6 | Packages are three read-only registry entries, one per manager, plus one for `[tools]`. Not one setting per package. | A package has no value to set (P3). 367 rows would bury the real settings. Removing one needs `prune`, which is not a reset. |
| P7 | `upup` never prunes. | `prune --manager brew` removes every undeclared formula, including ones installed by hand. It stays a documented manual command with `--dry-run` first. |

- [ ] **Step 1: Write the failing self-check `bin/lib/test-packages`**

A bash script with the repo's header form (see `bin/lib/test-conventions:1-31`), `set -euo pipefail`, `cd` to the repo root, a `fail()` helper. It runs one embedded Python block with `mise exec python -- python3` when `mise where python` exits 0, else plain `python3` (the same switch `bin/lib/check:47-53` uses). The block loads the fragment with `tomllib` and asserts:

```python
doc = tomllib.loads(Path("tilde/.config/mise/conf.d/30-packages.toml").read_text())
pk = doc["bootstrap"]["packages"]
brew = doc["bootstrap"]["brew"]
taps = brew["taps"]
assert brew.get("adopt") is True, "[bootstrap.brew] adopt must be true"
assert "homebrew_metadata" not in brew, "homebrew_metadata hands casks back to Homebrew"
assert all(v == "latest" for v in pk.values()), "every package value is \"latest\": no pins, no inline tables"
managers = {k.split(":", 1)[0] for k in pk}
assert managers == {"brew", "brew-cask", "vscode"}, managers
for key in pk:
    manager, name = key.split(":", 1)
    if manager != "vscode" and name.count("/") == 2:
        owner, tap, _ = name.split("/")
        assert taps.get(f"{owner}/{tap}") == f"https://github.com/{owner}/homebrew-{tap}.git", f"undeclared tap for {key}"
    if manager == "vscode":
        assert name == name.lower() and re.fullmatch(r"[a-z0-9-]+\.[a-z0-9-]+", name), key
used = {"/".join(k.split(":", 1)[1].split("/")[:2]) for k in pk if k.count("/") == 2}
assert set(taps) == used, f"tap declared but unused, or used but undeclared: {set(taps) ^ used}"
assert len(taps) <= 5, "more than 5 taps: a new Mac runs out of anonymous GitHub API calls (Review Focus 1)"
assert "brew:mise" not in pk, "mise is installed by its own installer"
count = lambda m: sum(k.startswith(m + ":") for k in pk)
assert (count("brew"), count("brew-cask"), count("vscode")) == (143, 33, 183), "counts changed: update this line with the entry you added or removed"
```

## Handoff to Part B

What `migrate/legacy-to-mise --step packages` needs from this phase. A4 writes none of it.

1. **mise first.** Install mise with `curl -fsSL https://mise.run | sh`, confirm `~/.local/bin/mise --version` is at or above the floor, and confirm a new login shell resolves `mise` to it only after the old one is gone. The old `/opt/homebrew/bin/mise` is one of the kegs prune removes, and it is the binary doing the pruning if PATH still puts it first. So run prune as `~/.local/bin/mise`. `upup`'s mise MCP check re-registers the server on its own when the path changes.
2. **Which casks.** `mise bootstrap packages status --json | jq -r '."brew-cask".packages[] | select(.managed_by == "homebrew" and (.auto_updates | not)) | .package'`. On this Mac that is the 16 listed in [Measured](#measured-on-this-mac-2026-11-09-mise-2026115). Self-updating casks need no migration: mise never upgrades those anyway. Per chosen cask: quit the app, `brew uninstall --cask <token>`, `mise bootstrap packages apply brew-cask:<token> --yes`, check `managed_by` is `mise`. Warn about privacy permissions before each app cask. Fonts and CLI casks carry no such risk.
3. **Undeclared formulae.** With a clean state dir the prune dry-run lists 11 kegs: the 7 D6 formulae and `mise` (expected), `openssl@3@3.5.9` (an unlinked old keg), and `ai-kb-lite` and `aikb`. Ask about the last two: keep them by declaring them in the machine-local `config.local.toml`, or let prune remove them. Whether `[bootstrap.packages]` in `config.local.toml` is honoured is not verified: `mise bootstrap packages status` after adding one entry there settles it.
4. **Tracked configs hide prune targets.** Clean `~/.local/state/mise/tracked-configs` of links to deleted scratch dirs first (`mise prune` semantics do not apply here; inspect the dir), or the dry-run under-reports.
5. **Undeclared casks.** `gcloud-cli`, `signal`, `t3-code` are Homebrew's and in no config. mise will never touch them. List them and ask.
6. **Staging-lock leftover.** After `brew uninstall` of a formula that mise poured, an empty `Cellar/<name>` holding `.mise-staging.lock` remains and `brew list --versions <name>` still prints the name. Remove such a directory when it holds nothing else.
7. **The rustup record.** Task 5 already created `var/homebrew/linked/rustup`. Nothing to migrate.
8. **Uninstalling Homebrew** (offered last, never by default) removes `/opt/homebrew/Library`, which `bin/ca-roots trim` needs (P10). Say so in the prompt.

## Spec gaps

Places the spec is wrong or silent. None is worked around silently; each has a decision above.

1. **"15 formulae" counts two that are not in the Brewfile** (`ai-kb-lite`, `aikb`). The Brewfile has 13 bottle-less tap formulae and 12 taps, not 13.
2. **D6 says "mise's registry carries".** For `kubelogin` the registry short name is the wrong project and only the explicit `aqua:Azure/kubelogin` is right. For `sentry` no backend is right, so it stays a tap formula.
3. **`upup` is split between A4 and A6** ("stop calling `brew`" here, "uses `mise bootstrap packages upgrade`" there). Upgrades cannot stop for a phase, so A4 adds the step. plan-a6 was told.
4. **`bin/ca-roots` depends on Homebrew's own Ruby script and portable Ruby.** The spec lists `DOTFILES_TRIM_CA_ROOTS` as a setting and never says the feature needs Homebrew's files. On a Homebrew-free Mac the trim cannot run, and the `brew doctor` warning that pointed at it is gone. P10 keeps the step where the files exist. A native trim is a separate piece of work for the user to accept or decline.
5. **`bin/rea-mcp` and `setup/misc.sh:363` call `brew --prefix`.** The spec's "other `brew` callers" does not name them.
6. **`trusted:` has no equivalent.** The spec does not say what replaces the per-package trust check. This plan uses the declared tap URL list, checked by `test-packages`.
7. **The anonymous GitHub rate limit** is not in the spec's risks. It decides whether a new Mac can install tap formulae before `gh auth login`.
8. **`.claude/rules/telemetry-sync.md` and `colors/README.md`** are in the spec's A4 documentation row and hold nothing to change.
