# A4 Packages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every formula, cask and VS Code extension this repo installs is declared in mise's config and installed, upgraded and reported by mise, and nothing in setup, `sysup` or shell startup calls `brew`.

**Architecture:** `tilde/.config/mise/conf.d/30-packages.toml` replaces `setup/Brewfile`. Seven tap formulae move to `[tools]`. An in-repo package-manager plugin at `mise-plugins/vscode/` installs the extensions. `setup/packages.sh` replaces `setup/brew.sh`: it installs mise with mise's own installer, links the plugin and applies the packages. Shell startup gets static lines in place of `brew shellenv`. `sysup` upgrades through `mise bootstrap packages upgrade`. The settings package gains a read-only `package` adapter with one entry per manager.

**Tech Stack:** mise 2026.11.5 (`bootstrap packages`, package-manager plugins in Lua), bash 3.2, zsh 5.9, Python 3.11+ standard library, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-09-mise-first-setup-and-settings-ui.md`, phase "A4. Packages", decisions D5, D6, D11, D12. Read it first.

## Global Constraints

- Minimum mise version: 2026.11.5.
- The new method is Homebrew-free. Setup, `sysup` and shell startup never call `brew` (D5).
- Part A never reads the old layout and carries no compatibility code for it. What only an early adopter needs goes in [Handoff to Part B](#handoff-to-part-b).
- The package's core imports nothing outside the standard library. Its tests run with plain `python3`.
- Shell startup must not run an interpreter or mise unless a cached file is stale.
- Bash scripts start with `#!/bin/bash` and a header comment, define their output helpers inline, and pass `pnpm check`.
- Commit subjects are short, imperative, sentence case, with no conventional-commit prefix.
- GitHub Actions are pinned to a commit SHA with the version in a comment, as in `check.yml`.
- Every phase updates the docs that describe what it changed, in the same commit (D12).
- Tests that isolate mise set `MISE_CONFIG_DIR`, `MISE_DATA_DIR`, `MISE_STATE_DIR` and `MISE_CACHE_DIR`. Never set `MISE_GLOBAL_CONFIG_FILE`.
- **Never run these without the user's explicit go-ahead in chat:** `mise bootstrap packages apply`, `upgrade` or `prune` without `--dry-run`, `mise self-update`, `mise install`, `mise plugins link`, `bin/vscode-settings` without `--check`, `./setup.sh`, `sysup`, any `brew` command that changes state. Each step that changes the machine says so in its title, says who runs it, and waits for a yes. Tasks 5 and 6 are the only places a real package apply runs.
- Any `brew` command a step still runs after Task 3 is prefixed with `HOMEBREW_NO_ANALYTICS=1`. Task 3 deletes the export, and measured without it `brew analytics state` prints "InfluxDB analytics are enabled."
- Commits name their paths. No `git add -A`, no `git add .`, no bare directory. The working tree holds an unrelated uncommitted change to `agents/claude-settings.json` that must never enter a commit of this plan.
- A phase is done when `pnpm check` and this plan's self-checks pass. `mise bootstrap status --missing` is informational: apps rewrite preferences on their own, so it can exit 1 without cause.
- Line numbers are from commit `9af6244`. An earlier phase may have moved them, so find the quoted text with `grep -n` before editing.

## Measured on this Mac (2026-11-09, mise 2026.11.5)

The implementer cannot re-derive these cheaply. Each was run in a scratch `MISE_CONFIG_DIR`.

**Status JSON.** `mise bootstrap packages status --json` prints one object keyed by manager:

```json
{
  "brew": { "available": true, "packages": [
    { "package": "ack", "requested_version": "latest", "desired_state": "present", "state": "installed", "installed_version": "3.10.0" } ] },
  "brew-cask": { "available": true, "packages": [
    { "package": "cmux", "requested_version": "latest", "desired_state": "present", "state": "installed", "installed_version": "0.65.2.2", "auto_updates": true, "managed_by": "homebrew" } ] },
  "vscode": { "available": true, "packages": [
    { "package": "eamodio.gitlens", "requested_version": "latest", "desired_state": "present", "state": "missing", "installed_version": "" } ] }
}
```

`managed_by` appears on casks only (`"homebrew"`, `"mise"` or `"unknown"`). `auto_updates` appears only when true. Formulae carry neither. States seen: `installed`, `missing`, `needs_repair` (JSON uses an underscore, the table prints "needs repair") and `skipped`. `status --missing` exits 1 on `missing` and `needs_repair`. With 184 packages the command took 0.7 s.

**An unavailable manager.** Without `code` on PATH the `vscode` manager reports `"available": false`, every one of its packages has `"state": "skipped"`, and `status --missing` exits 0. So a reader of this JSON treats a manager with `available == false` as one fact, not as 183 packages. When `code` is on PATH and `code --list-extensions` exits non-zero, the whole `status` command fails, for every manager. `sysup` then reports its `couldn't read package state` failure (Task 7) and the adapter shows `status failed` on its three manager entries (Task 9).

**Ruby.** mise evaluates a tap's Ruby definition with Ruby 3 or newer when Homebrew publishes no metadata for it. macOS ships 2.6. Measured with `PATH=/usr/bin:/bin` and a config holding `brew-cask:jrmatherly/tap/claude-multipass-app`: `status --json`, `status --missing` and `apply --manager brew-cask --dry-run` all exit 1 with `evaluating the tap definition for claude-multipass-app requires Ruby 3 or newer`. `apply --manager brew --dry-run` on the same config succeeds, tap formula included. Here a Ruby 3 exists only as `/opt/homebrew/bin/ruby`, an undeclared dependency of `ruby-lsp`. So the fragment declares `"brew:ruby"`, and `setup/packages.sh` applies formulae before casks.

**Completions.** `/opt/homebrew/share/zsh/site-functions` holds `_flux` and `_talosctl`, installed by the two tap formulae. None of the seven D6 tools has another completion file there. The `[tools]` versions ship none, and the repo has no step that generates completion files (`zsh/zsh-completions` holds three hand-kept files from the first commit). See P13.

**Config keys.** `[bootstrap.brew] adopt` and `homebrew_metadata` parse. An unknown key under `[bootstrap.brew]` is a warning. `"brew:trash-cli" = { version = "latest", link = true }` is `mise::config::parse_error`. A plugin key such as `"vscode:golang.go"` needs the plugin linked, or the manager shows as unavailable.

**`brew shellenv zsh` prints exactly:** `HOMEBREW_PREFIX`, `HOMEBREW_CELLAR`, `HOMEBREW_REPOSITORY` (all `/opt/homebrew` based), `fpath[1,0]="/opt/homebrew/share/zsh/site-functions"` with `export FPATH`, `PATH="/opt/homebrew/bin:/opt/homebrew/sbin:$PATH"`, a `MANPATH` line that only reformats an already-set `MANPATH`, and `INFOPATH="/opt/homebrew/share/info:${INFOPATH:-}"`. In this repo only `HOMEBREW_PREFIX` is read (`zsh/init.zsh:8`, `bin/sysup:471`, `bin/ca-roots:40`, `bin/lib/test-shell:121`).

**The rustup repair.** `status` reports `rustup` as `needs_repair`, and a dry-run apply prints `repair rustup/1.29.3: linked-keg record`. From mise's source at tag `v2026.11.5` (`crates/mise-system-packages/src/brew/pour.rs`, `pending_record_repair` and `repair_link_record`): when a formula's `opt` link is valid, its keg has no `.mise-keg-only` marker file, `var/homebrew/linked/<name>` is absent, and some file under the prefix's `bin`, `lib` and similar dirs links into the keg, mise creates the one symlink `/opt/homebrew/var/homebrew/linked/rustup -> ../../../Cellar/rustup/1.29.3`. It does not relink the keg (the unit test is named `test_repairs_active_records_without_relinking_the_keg`). The trigger here is `/opt/homebrew/bin/rustup`, which the formula's own post-install step links (`post_install_steps` in `https://formulae.brew.sh/api/formula/rustup.json`). Homebrew poured the keg, so the marker is missing and mise mistakes a keg-only formula for a linked one. Task 5 confirms this by diff before anything else is applied.

## Decisions this plan makes

| # | Decision | Why |
| --- | --- | --- |
| P1 | `30-packages.toml` is generated once by a script the implementer writes in the scratchpad and never commits. | 360 package entries with comments: 144 formulae, 33 casks, 183 extensions, plus 5 taps. The 144 are the Brewfile's 151, minus `mise`, minus the 7 that move to `[tools]`, plus `brew:ruby`. A one-off script is checked by counts. Hand-copying is not. |
| P2 | `[bootstrap.brew] adopt = true`. `homebrew_metadata` is not set. | `adopt` keeps an app that is already in `/Applications` instead of replacing it (replacing drops privacy permissions), and fails without touching it when it is a different build. `homebrew_metadata = true` hands each cask to Homebrew and makes mise skip it in apply, upgrade and prune, which is the opposite of D5. |
| P3 | No version pins and no `link`. `test-packages` rejects any value but `"latest"`. | mise cannot install an old bottle or cask. A pinned entry is skipped with a warning forever. |
| P4 | `brew "mise"` is dropped. mise comes from `https://mise.run` into `~/.local/bin/mise`. `sysup` runs `mise self-update --yes`. | The spec. A formula entry would need mise to install mise. On this Mac mise stays Homebrew's keg until Part B's `packages` step moves it (Handoff item 1), and nothing upgrades it in between (Task 7 Step 7). |
| P5 | `bin/brewpick` is deleted with no replacement script. | A subset install is `mise bootstrap packages apply brew:<name>`. The settings UI shows what is missing and `apply package` installs it. The `manual "MonoLisa"` entry was a link opener; `fonts/README.md` already has the link. |
| P6 | Packages are three read-only registry entries, one per manager, plus one for `[tools]`. Not one setting per package. | A package has no value to set (P3). 360 rows would bury the real settings. Removing one needs `prune`, which is not a reset. |
| P7 | `sysup` never prunes. | `prune --manager brew` removes every undeclared formula, including ones installed by hand. It stays a documented manual command with `--dry-run` first. |
| P8 | `fresh-install.yml` runs `setup/packages.sh`, so it always installs casks and extensions too. It has no formulae-only input. | The job exists to test the path a new Mac takes, and that path is the script: the mise installer, the config-dir export, formulae, then casks, then extensions. Casks are also the part this Mac cannot test (pkg installers, generated completions). The runner has passwordless sudo. A formulae-only mode would need an option in `setup/packages.sh` that only CI uses. |
| P9 | `check.yml` installs its four tools with `mise bootstrap packages apply brew:…` instead of `brew install`. | A1 already installs mise there. It makes every CI run a small install test. |
| P10 | The opt-in CA-roots step in `sysup` stays but runs only where Homebrew's script still exists. | `bin/ca-roots trim` runs Homebrew's own Ruby script. See [Spec gaps](#spec-gaps). |
| P11 | `export HOMEBREW_PREFIX=/opt/homebrew` stays, in `tilde/.zprofile`. Do not delete it. | The spec says the `HOMEBREW_*` exports go. That holds for the eight in `zsh/env.zsh`, which only `brew` and `bin/brewpick` read. `HOMEBREW_PREFIX` names the prefix mise installs into, and `zsh/init.zsh`, `bin/sysup`, `bin/ca-roots` and `bin/rea-mcp` read it. |
| P12 | `"brew:ruby"` is declared. | mise needs Ruby 3 or newer to read the `claude-multipass-app` tap cask (see Measured, Ruby). Without the entry it is present only as a dependency of `ruby-lsp`. |
| P13 | The `flux` and `talosctl` zsh completions are not restored. The docs say so and give the one command that writes each. | The repo has no step that generates completion files, and a generated file committed to `zsh/zsh-completions` would go stale against a tool pinned to `latest`. A generation step is new machinery for two commands. |
| P14 | `"mise.binPath"` is deleted from `vscode/User/settings.json.j2`. | It is `/opt/homebrew/bin/mise`, which does not exist on a new Mac and goes away here in Part B. The extension's default is `mise`, documented in its `package.json` (`hverlin.mise-vscode` 1.32.0) as "it will use `mise` available in `PATH`", and `tilde/.zprofile` puts `~/.local/bin` on the PATH VS Code resolves from the login shell. That last step is inferred, so Task 4 Step 6 has the user confirm it in VS Code. |
| P15 | `.claude/settings.json` gains ask rules for `mise install*`, `mise self-update*` and `mise plugins link*`. | The repo's rule for `sysup` and `set-defaults` is that every way to start a command that changes the machine asks. In this repo the global config is the repo's own, so `mise install` installs the tracked tools. A3's `Bash(mise bootstrap*)` already covers `mise bootstrap packages …`. |
| P16 | `[bootstrap.brew.taps]` is a reviewed list, not a trust boundary. | mise finds `owner/tap` at its default GitHub URL with no entry, so `mise bootstrap packages apply brew:any/tap/x` typed by hand bypasses the list. Only `test-packages` enforces it, and only for the tracked fragment. The add-tool skill says so (Task 10). |

## Spec gaps

Places the spec is wrong or silent. None is worked around silently; each has a decision above.

1. **"15 formulae" counts two that are not in the Brewfile** (`ai-kb-lite`, `aikb`). The Brewfile has 13 bottle-less tap formulae and 12 taps, not 13.
2. **D6 says "mise's registry carries".** For `kubelogin` the registry short name is the wrong project and only the explicit `aqua:Azure/kubelogin` is right. For `sentry` no backend is right, so it stays a tap formula.
3. **`sysup` is split between A4 and A6** ("stop calling `brew`" here, "uses `mise bootstrap packages upgrade`" there). Upgrades cannot stop for a phase, so A4 adds the step. plan-a6 was told.
4. **`bin/ca-roots` depends on Homebrew's own Ruby script and portable Ruby.** The spec lists `DOTFILES_TRIM_CA_ROOTS` as a setting and never says the feature needs Homebrew's files. On a Homebrew-free Mac the trim cannot run, and the `brew doctor` warning that pointed at it is gone. P10 keeps the step where the files exist. A native trim is a separate piece of work for the user to accept or decline.
5. **`bin/rea-mcp` and `setup/misc.sh:363` call `brew --prefix`.** The spec's "other `brew` callers" does not name them.
6. **`trusted:` has no equivalent.** The spec does not say what replaces the per-package trust check. This plan uses the declared tap URL list, checked by `test-packages`.
7. **The anonymous GitHub rate limit** is not in the spec's risks. It decides whether a new Mac can install tap formulae before `gh auth login`.
8. **`.claude/rules/telemetry-sync.md` and `colors/README.md`** are in the spec's A4 documentation row and hold nothing to change.
9. **"The `HOMEBREW_*` exports go" is too broad.** `HOMEBREW_PREFIX` stays, exported from `tilde/.zprofile` (P11). The eight in `zsh/env.zsh` go, and with them A2's `privacy.homebrew_no_analytics` setting (Task 3 Step 3a).
10. **No phase moves mise itself off the Homebrew keg on a Mac that is already set up.** A4 stops `sysup` upgrading it through `brew`, and the keg refuses `mise self-update`. Handoff item 1 gives Part B the action, and Task 7 Step 7 tells the user about the gap before the commit that opens it.
11. **mise needs Ruby 3 or newer to read a tap cask**, and the spec's package list has none. P12 declares `brew:ruby`.
12. **`[bootstrap.brew.taps]` is not a trust boundary** (P16). The spec treats the tap list as the replacement for `trusted:`. It is a reviewed list that one test enforces.
13. **Two zsh completions are lost** (`flux`, `talosctl`, P13). The spec's D6 does not mention completions.
