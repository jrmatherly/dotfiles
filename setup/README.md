# Setup Scripts

## setup.sh (wrapper)

![setup.sh runtime: the step scripts, what they fetch from the internet, what runs as root, and what lands in $HOME](bootstrap-runtime.svg)

The diagram is generated with [Archify](https://github.com/tt-a1i/archify) from [`bootstrap-runtime.archify.json`](bootstrap-runtime.archify.json), whose source line references are pinned to a commit. When the step order, sudo use or download sources change, update that file, re-run `archify finalize` and re-export the SVG.

`../setup.sh` is a wrapper around `mise bootstrap`. It resolves its own location, so the repo can live anywhere. In order, it:

1. Stops when the Xcode Command Line Tools are missing, and prints `xcode-select --install`.
1. Links `~/dotfiles` to the clone and `~/.config/mise` to the clone's `tilde/.config/mise`, when nothing is at those paths. When either is something else it stops before installing anything, and for `~/.config/mise` it prints the `mv` command that moves it aside. Every `[dotfiles]` source is written `~/dotfiles/…`, and mise reads the whole setup through `~/.config/mise`: with another config there it would find no packages, no dotfiles and no task, and exit 0.
1. Installs mise when no `mise` is on PATH, then runs [`mise-floor.sh`](mise-floor.sh) and stops when mise is older than 2026.11.5.
1. Asks for the administrator password once (see below).
1. Links the [dotfiles](#dotfiles) with `mise dotfiles apply` from `$HOME` (with `--dry-run` on a dry run, not at all with `-- --skip dotfiles`), and stops when the apply fails. Packages write into `$HOME` (the git-credential-manager pkg writes `~/.gitconfig`, `code` creates `~/Library/Application Support/Code/User`), and a real file where a link belongs would stop the apply, so it comes first.
1. Applies the [packages](#packages), one manager at a time. A package that fails only warns.
1. Runs `mise bootstrap --skip macos-defaults,packages,tools,task` from `$HOME`. mise's parts run in its own fixed order: system files (Touch ID for `sudo`), dotfiles (already applied, so nothing to do) and the [login shell](#login-shell). Then it drops the sudo credential.
1. Installs the tools with `mise install --yes` from `$HOME`, and with `-- --upgrade` runs `mise upgrade --yes` after it, as mise's `tools` part would. mise stops the whole bootstrap at a tool that fails, so `setup.sh` runs this step itself: `mise install` carries on past a failed tool and exits 1, and `setup.sh` then reads `mise ls --missing --json` for the tools still missing.
1. Runs the `bootstrap` task, [`misc.sh`](#misc), with `mise bootstrap --only task`. It is a second call because inside one bootstrap the task runs right after the skipped `tools` part, before the tools exist.
1. Applies the VS Code extensions (see [packages](#packages)).
1. Runs [`dotfiles-extras.sh`](#dotfiles-extrassh), then moves any `[credential]` section out of the tracked `tilde/.gitconfig` into `~/.gitconfig.local` (the git-credential-manager pkg registers itself with `git config --global`, and `~/.gitconfig` is a link into the repo). Then `dash.sh` with `--dash`.
1. Prints "All done" and exits 0. When a package, a tool or an upgrade failed, it prints the list of them instead, as the last thing on screen, each with its kind (formula, cask, extension, tool, upgrade) and mise's own `failed:` or `ERROR` text when it printed one, and exits 2.

A run is not a transaction. When a part of `mise bootstrap` or the task fails, mise stops there, `setup.sh` exits with its status, and the earlier steps stay applied. Fix what it reported and rerun `./setup.sh`: every step is safe to repeat, and the hooks and the `bootstrap` task run on every bootstrap. Exit status 2 means the run got to the end and only the listed items failed. A tool's reason is mise's one line; `mise install <tool>` from `~` shows the whole error.

Flags: `-y/--yes` (also passed to mise, and exported as `DOTFILES_YES` so `misc.sh` skips its font preset menu and its `gh auth login` question), `--skip-codegraph`, `--dash`, `-h/--help` and `-- <args>`, described in the table in the [main README](../README.md#run-setup). Everything after `--` goes to `mise bootstrap`, with these exceptions:

The manual [`fresh-install`](../.github/workflows/fresh-install.yml) workflow (`gh workflow run fresh-install.yml`) runs `./setup.sh` on a hosted runner without Homebrew. A runner is not a clean Mac (Xcode is preinstalled and sudo asks for no password), so it does not replace a run on a new Mac.

- `--skip <parts>` is merged into the one `--skip` list that setup passes. `--skip packages` also skips setup's own package step, `--skip tools` its `mise install`, `--skip task` the second bootstrap call, and `--skip dotfiles` also skips `dotfiles-extras.sh`.
- `--only` is refused, because mise does not accept it together with `--skip`. Run `mise bootstrap --only <parts>` from `~` instead.
- `--upgrade` also upgrades the packages and tools: a `mise bootstrap packages upgrade` after each manager's apply and a `mise upgrade` after the tools install. mise's own `--upgrade` acts only in the `packages` and `tools` parts, which setup skips. A run without it installs what is missing and upgrades no package or mise tool (the task still updates PowerShell and a changed Iosevka Code font). `sysup` is the command that upgrades everything, macOS and mise included.
- `--dry-run` also reaches the package step and the tools install and upgrade. The two links and the mise install still happen. The sudo prompt, the plugin link and `dotfiles-extras.sh` are left out.

`--skip-brew` is gone: it exits 1 and names `./setup.sh -- --skip packages`.

With a terminal, and not on a `--dry-run`, it asks for the administrator password once (`sudo -v`) and keeps the sudo timestamp alive for the steps that need root: the packages (cask installers), `/etc/pam.d/sudo_local` and the login shell. All of them run before the tools. `setup.sh` runs `sudo -k` after the first `mise bootstrap` call, the `pre-tools` hook in [`50-bootstrap.toml`](../tilde/.config/mise/conf.d/50-bootstrap.toml) does the same for a bare `mise bootstrap`, and `misc.sh` starts with it too, so npm install scripts, the `curl | bash` installers and the uv and dotnet installs cannot use sudo without asking. `dotfiles-extras.sh` runs after that. It asks for the password itself, and only when it has to link `cot` or `code` into `/usr/local/bin`. Without a terminal there is no `sudo -v`, and mise asks for sudo at each step that needs it.

Touch ID for `sudo` is the file `/etc/pam.d/sudo_local`, declared under `[bootstrap.files]` with its content, mode `0644` and owner `root:wheel`. mise rewrites it when any of them differs.

With `TERM` unset (a launchd job, CI), the scripts print without colors instead of aborting on a failed `tput`.

When run from a terminal, it records the whole run (prompts included) to `private/setup-logs/<timestamp>.log`, which is git-ignored, by re-running itself under macOS `script`. `/validate-setup after` reads the newest log, so there's no need to paste output.

The macOS preferences are deliberately not part of the run; use `set-defaults`. `setup.sh` always passes `--skip macos-defaults`, which also drops the `pre-defaults` and `post-defaults` hooks around that part. A bare `mise bootstrap` does apply them and restarts Finder and the Dock, so `./setup.sh` is the rerun command.

To preview a run without changing anything, once `~/.config/mise` is the link: `cd ~ && mise bootstrap --dry-run --skip macos-defaults`. The [main README](../README.md#preview) has the form for a Mac without the link.

## packages

`setup.sh` installs everything declared in [`tilde/.config/mise/conf.d/30-packages.toml`](../tilde/.config/mise/conf.d/30-packages.toml) with `mise bootstrap packages apply`, before `mise bootstrap` and with the `packages` part skipped there. mise downloads Homebrew's bottles and casks into `/opt/homebrew` itself; Homebrew is not installed and `brew` is never run. Pass `-- --skip packages` to `setup.sh` to leave the packages alone. In order, it:

1. Installs mise with mise's own installer (`curl -fsSL https://mise.run | sh`, into `~/.local/bin`) when no `mise` is on PATH.
1. Warns when gh has no GitHub token and `MISE_GITHUB_TOKEN` is unset, then carries on. Tap formulae resolve through GitHub's API, whose anonymous limit is 60 calls an hour. `setup.sh` exports no token: mise asks gh for one itself (`[settings.github] credential_command` in `tilde/.config/mise/config.toml`), since gh keeps it in the Keychain where mise can't read it.
1. Links the in-repo VS Code plugin (`mise plugins link --force vscode mise-plugins/vscode`).
1. Applies the formulae, then the casks, one `mise bootstrap packages apply --yes --manager <name>` each, from `$HOME` so a project's config can't add to the run, and prints the free disk space after each. Formulae go first because reading a tap's cask needs the Ruby that `brew:ruby` installs.
1. Applies the VS Code extensions the same way, after the `bootstrap` task has succeeded. When a bootstrap call fails, the run stops before the extensions; rerun `./setup.sh`. They are also skipped with a message while VS Code's `code` command isn't on PATH; rerun `./setup.sh` once it is. With `-- --upgrade`, each apply is followed by `mise bootstrap packages upgrade --yes --manager <name>`.

A package that fails to install or upgrade warns and setup carries on; rerun `./setup.sh`. mise's apply stops at the first package that fails, so after a failed apply `setup.sh` reads `mise bootstrap packages status --json` and applies each package of that manager still missing on its own (`mise bootstrap packages apply --yes <manager>:<name>`), warning for each one that fails again and listing it at the end of the run. It stops only when mise read no package list at all. mise itself stops at the first part that fails, which is why `setup.sh` applies the packages: a bare `mise bootstrap` runs the `packages` part without that tolerance (its `pre-packages` hook links the plugin), and one failed cask would skip the dotfiles, the login shell and the tools.

What to know about the package list:

- **Keys and values.** Each entry is `"brew:<formula>"`, `"brew-cask:<cask>"` or `"vscode:<publisher.id>"`, and every value is `"latest"`. mise installs only the current bottle or cask, so a pinned version would be skipped with a warning.
- **Apps already installed.** `adopt = true` under `[bootstrap.brew]` keeps an app that is already in `/Applications` instead of replacing it, since a replaced app loses its privacy permissions.
- **Whose cask it is.** A cask mise installs is mise's to upgrade. A cask that Homebrew put there earlier is left alone, and `sysup` counts the ones that don't update themselves in a notice. The command that hands them to mise is `migrate/legacy-to-mise --step packages`.
- **Warp.** Its cask URL answers 404 unless the User-Agent starts with `Homebrew`, and mise has no setting for its own. `[settings.url_replacements]` in [`tilde/.config/mise/config.toml`](../tilde/.config/mise/config.toml) rewrites that request to the release file the URL redirects to, and the cask's checksum still verifies the download.
- **Removing an entry uninstalls nothing.** `mise bootstrap packages prune` does that. Run `mise bootstrap packages prune --manager brew --dry-run` first: it removes every formula no config declares, the ones you installed by hand included.
- **Taps.** The four third-party taps under `[bootstrap.brew.taps]` are the reviewed list. A package from one is written `owner/tap/name`, and `bin/lib/test-packages` fails when a tap is used but not listed, listed but unused, or the list grows past five. The list is a review step, not a trust boundary: mise resolves an undeclared `owner/tap` at its default GitHub URL, so `mise bootstrap packages apply brew:owner/tap/x` typed by hand goes around it.
- **No man pages.** mise links no man pages, so `man ghostty` finds nothing where mise installed Ghostty.
- **No services.** There is no `brew services`; no package here needs one.
- **Shell.** [`tilde/.zprofile`](../tilde/.zprofile) sets `HOMEBREW_PREFIX`, `PATH`, `fpath` and `INFOPATH` with static lines, the ones `brew shellenv` used to print. Scripts read `HOMEBREW_PREFIX`, so keep it.

Eight tools that Homebrew taps used to supply are mise `[tools]` in [`config.toml`](../tilde/.config/mise/config.toml) instead, installed with the other tools by `setup.sh`'s `mise install` (or the `tools` part of a bare `mise bootstrap`): `azd`, `azure-functions-core-tools` (`func`), `aqua:Azure/kubelogin`, `flux2` (`flux`), `hunk`, `lazydocker`, `talosctl` and the Sentry CLI (`github:getsentry/toolkit`, binary `sentry`). The Aspire CLI and `flate` are `github:` tools there too. `mirrord` is a tool there because its VS Code extension only downloads the binary after a version check that the telemetry-off setting disables. `flux2`, `talosctl` and `sentry` carry a mise `postinstall` that writes their zsh completions to `~/.cache/dotfiles/completions` on every `mise install` and every upgrade, and `zsh/completion.zsh` puts that directory first in `fpath`. A new completion shows up in a shell started after the file exists; a shell whose `~/.zcompdump` is under a day old may need `rm -f ~/.zcompdump` once, because `compinit -C` skips the scan.

**.NET / PowerShell:** the list uses Microsoft's `dotnet-sdk` cask. Don't add the `dotnet` or `powershell` formulae — `powershell` depends on `dotnet`, and that formula takes over `/opt/homebrew/bin/dotnet`. PowerShell is installed as a .NET global tool by `misc.sh` instead.

## login shell

`[bootstrap.user]` in [`50-bootstrap.toml`](../tilde/.config/mise/conf.d/50-bootstrap.toml) declares `/opt/homebrew/bin/zsh` (the `brew:zsh` package) as the login shell. mise adds it to `/etc/shells` and runs `chsh` when the account's shell differs. When it is already the shell, mise reports `already set` and changes nothing.

## misc

[`misc.sh`](misc.sh) is the `bootstrap` task (`[tasks.bootstrap]` in [`50-bootstrap.toml`](../tilde/.config/mise/conf.d/50-bootstrap.toml)): every step no declarative mise section covers. It runs on every `mise bootstrap`, after the tools, so each step checks state first and warns instead of failing. It never uses sudo. It also runs on its own (`setup/misc.sh`).

- Makes the scripts in `bin/` executable.
- Installs the [Iosevka Code](https://github.com/amnweb/Iosevka-Code) Nerd Font (VS Code's font, no cask) into `~/Library/Fonts` with [`bin/install-iosevka-code`](../bin/install-iosevka-code). Unlike the rest of setup it also updates: if the upstream release zip changed since the last install, it's reinstalled (see [fonts](../fonts/README.md)). A failed download warns and setup carries on.
- Renders VS Code's `settings.json` from `vscode/User/settings.json.j2` with [`bin/vscode-settings`](../bin/vscode-settings) (minijinja-cli, a `brew:` package), offering the font preset menu (`iosevka`, `warp`, `warp-terminal`, `fira`) when run from a terminal and keeping the saved choice otherwise. It never overwrites changes VS Code made since the last render: that's a warning with the diff, and `vscode-settings --force` drops them. Without minijinja-cli (a fresh Mac whose run skipped the packages) it's skipped with a warning. See [vscode/README.md](../vscode/README.md#fonts-and-the-settings-template).
- If the GitHub CLI isn't authenticated, offers to run `gh auth login`. gh keeps the token in the macOS keychain; `~/.config/gh/hosts.yml` is gitignored anyway, since gh falls back to storing the token there in plain text when no keychain is available.
- The runtimes and CLIs are there before this task: `setup.sh`'s `mise install` (or the `tools` part of a bare `mise bootstrap`) installs them from the tracked global config [`tilde/.config/mise/config.toml`](../tilde/.config/mise/config.toml), which `setup.sh` linked into `~/.config/mise`. When a tool lists several versions, mise installs all of them and the first is the default on PATH. A tool that fails to install is listed at the end of the run, and the task runs anyway; rerun `./setup.sh`. In a bare `mise bootstrap` it stops the run at the `tools` part, before this task. The task itself only puts mise's shims on its PATH and links TypeScript (below):
  - Node `24` (Active LTS, pinned rather than the moving `lts` alias), plus `22` and `26`.
  - Python `3.14`, plus `3.11`–`3.13` and `3.15`. Every version's `python3.x` is on PATH.
  - `npm:typescript` (major 6), for a global `tsc`.
  - `npm:@colbymchenry/codegraph` ([CodeGraph](https://github.com/colbymchenry/codegraph)), tracking `latest`. Upgrade it with `mise upgrade`, not `codegraph upgrade`.
  - `npm:serverless` (major 4) and `npm:@antfu/ni` (major 30): global npm CLIs installed by mise instead of `npm install -g`.
  - the `npm:` language servers for [Terax](https://terax.app/)'s editor (the list and the PATH mechanism are explained in the config). Because mise gives every npm tool its own prefix, `typescript-language-server` can't see the global `npm:typescript`; the script links it at `<mise data dir>/node_modules/typescript`, where the server's own Node module resolution finds it, so files outside a project with TypeScript get a server too (`bin/sysup` relinks after `mise upgrade`, as the link target carries the exact version). Each preset is still switched on per machine in Terax's settings, which are app-written and not tracked.
  - `npm:rea-agents` ([REA](https://github.com/morluto/rea), the reverse-engineering MCP server and `rea` CLI), tracking `latest` with mise's release-age cutoff shortened from 24 h to 6 h (`minimum_release_age = "6h"`): REA publishes several releases a day, and the MCP registration below runs whatever mise installed, so nothing pins a stale version. The cutoff also applies to the tool's transitive dependencies, which is why it isn't zero. mise's embedded npm client ignores npm's `min-release-age`, which would otherwise hold it a week back.
  - [Bun](https://bun.com) (`latest`), which runs the jstack plugin's `j-mode` scripts from the skills repo.
  - `github:microsoft/aspire` (the Aspire CLI) and `github:home-operations/flate`, checksum-verified binaries from their GitHub releases rather than the projects' taps; the comment in the config says why and when to move them back.
  - the eight tools listed under [packages](#packages) above.

  The config also sets `idiomatic_version_file_enable_tools = ["node", "python"]`, which is off by default in mise. It makes mise honour `.nvmrc`/`.node-version` (like fnm and nvm) and `.python-version` (like pyenv and uv). This repo's own `.nvmrc` (`lts/*`) and `bin/nnn` both rely on this setting.

- Makes stable the default Rust toolchain through the keg-only [`rustup`](https://rust-lang.github.io/rustup/) formula (`rustup default stable`, skipped when `rustup default` already names stable or the formula is absent). The toolchain is installed up front because a proxy with no default downloads one on first use, inside the 10 s `cargo --version` preflight that Hindsight's daemon start runs on macOS. PATH order for the keg is explained in `zsh/path.zsh`; `sysup` runs `rustup update`. A project that pins another version uses mise's rust backend, which reuses this rustup.
- Installs [Claude Code](https://docs.claude.com/en/docs/claude-code/setup) with Anthropic's native installer (`curl -fsSL https://claude.ai/install.sh | bash`) into `~/.local/bin`, which `zsh/path.zsh` puts on PATH. It's skipped when `claude` already exists, since the native install updates itself. The `vscode:anthropic.claude-code` package is only the VS Code extension.
- Connects CodeGraph to Claude Code with `codegraph install --yes --target claude --location global`. This writes the MCP server to `~/.claude.json` (user scope), the `mcp__codegraph__*` permission and a `UserPromptSubmit` hook to `~/.claude/settings.json`, and a marker-fenced block to `~/.claude/CLAUDE.md`. Re-running updates the entries in place instead of duplicating them. Because the installer also rewrites `~/.claude/CLAUDE.md` by renaming a new copy over it, that file isn't tracked; global Claude instructions live in `tilde/.claude/rules/` instead. The step targets Claude Code only on purpose: the installer replaces files by writing a new copy and renaming it over the old one, so running it for Codex would turn the `~/.codex/AGENTS.md` symlink into a regular file. To add another agent, run `codegraph install --target <id>`, but only for agents whose config isn't symlinked into this repo. It then runs `codegraph telemetry off`, which persists the opt-out for agents launched outside a shell (`CODEGRAPH_TELEMETRY=0` in `zsh/env.zsh` covers shells). Indexing a project is still a manual step: `codegraph init` in that repo. Pass `--skip-codegraph` to `setup.sh` (or set `DOTFILES_SKIP_CODEGRAPH=true`) to skip CodeGraph's mise install and this step (the other mise tools still install). `setup.sh` then also sets `MISE_DISABLE_TOOLS=npm:@colbymchenry/codegraph` for the run, so a bare `mise bootstrap` needs both variables. Neither removes an existing install, and the task reshims once without `MISE_DISABLE_TOOLS` so an installed CodeGraph keeps its shim: use `codegraph uninstall` to remove it.
- Registers [mise's MCP server](https://mise.jdx.dev/mcp.html) with Claude Code at user scope as `mise` (`claude mcp add --scope user mise -- "$(command -v mise)" mcp`, i.e. the absolute path to mise) through `register_mcp` (below). The server lets the agent list mise tools, tasks, env and config, and run tasks. Its `mise://env` resource shows real environment values to the agent, secrets included. No `MISE_EXPERIMENTAL` is set: the server runs without it (checked on mise 2026.10.19).
- Installs [Serena](https://github.com/oraios/serena) with `uv tool install -p 3.13 serena-agent` if missing, and registers it with Claude Code at user scope (`serena start-mcp-server --context claude-code --project-from-cwd`) unless a `serena` server exists. Its bash language server only sees `*.sh`/`*.bash` files, so in this repo the extensionless `bin/` scripts are edited with the normal tools (`.claude/rules/code-navigation.md`).
- Installs [Scrapling](https://github.com/D4Vinci/Scrapling) with `uv tool install -p 3.13 "scrapling[ai]"` if missing (the `ai` extra is the MCP server plus the browser fetchers), runs `scrapling install` every time (it downloads Playwright's Chromium on the first run and is a no-op afterwards; `sysup` repeats it after a uv upgrade because the upgrade drops its marker file), and registers `~/.local/bin/scrapling-mcp` with Claude Code at user scope as `scrapling` through `register_mcp` (an absolute path, for the same reason as REA's shim), after importing the server module from the tool's venv: an earlier install without the `ai` extra still has the entry point, and `scrapling-mcp --help` passes there, so that case warns with the `--force` reinstall command instead of registering a server that dies on launch. Its tools fetch arbitrary URLs (plain HTTP, Chromium, or the stealth browser that bypasses Cloudflare Turnstile), with sessions and screenshots. The `scrapling-official` skill (the library author's, which tracks the library version) is an entry in `agents/claude-skills.txt`; it instructs agents to pass `--ai-targeted` to the `scrapling` CLI. No permission rules are set for its tools: all of them reach the network, so they go through the normal permission flow. [MCP server docs](https://scrapling.readthedocs.io/en/latest/ai/mcp-server/).
- Installs [Hindsight](https://github.com/vectorize-io/hindsight) coding-agent memory through `bin/hindsight-memory init` when `npx`, `uvx`, `jq` and `claude` are present: the vendor's installer (`@vectorize-io/hindsight-coding-agents`, pinned in the script) wires SessionStart, UserPromptSubmit and Stop hooks into Claude Code and Codex, registers a user-scope `hindsight` MCP server and the `hindsight-coding-agent` skill, and runs a local `hindsight-embed` daemon (profile `coding-agent`, port 9077, Postgres under `~/.pg0`). Each file it touches is backed up as `<file>.hindsight-backup`. Memory is opt-in: only sessions under the paths in `~/.hindsight/coding-agent.json` (`~/dev` by default, never tracked) get a bank, one per repo. Extraction runs on the Claude subscription (`HINDSIGHT_API_LLM_PROVIDER=claude-code`, exported in `tilde/.zshenv` for terminals and Codex started from one, and in `env` of the tracked Claude Code settings for app-launched sessions, because the hooks re-detect the provider from their environment on every daemon start; the models ride along the same way: `claude-sonnet-5-5` for reflect and the page refresh, `claude-haiku-5-5` for extraction and consolidation, since the provider's default `claude-sonnet-4-5-20250929` retires on 2026-11-30). Afterwards `hindsight-memory paths add|remove <dir>`, `on|off` (kill switch), `survey on|off`, `status` and `uninstall` (which keeps the config aside as `coding-agent.json.uninstalled`, so `sysup` skips the step until `init` restores it); `sysup` re-runs the pinned installer and reports a newer release. Design and privacy notes: `docs/superpowers/specs/completed/2026-10-24-hindsight-memory.md`, `docs/privacy.md`.
- Registers [REA](https://github.com/morluto/rea) with Claude Code at user scope as `rea`, command `bin/rea-mcp` (absolute path, so app-launched Claude Code finds it without the shell's PATH), but only when the `rea` shim, the `claude` CLI and the `ghidra` formula (`/opt/homebrew/opt/ghidra/libexec`) are all present; otherwise it prints a skip line and registers nothing. That launcher resolves `GHIDRA_INSTALL_DIR` (`${HOMEBREW_PREFIX:-/opt/homebrew}/opt/ghidra/libexec`) and `JAVA_HOME` (the default baked into the installed keg's `bin/ghidraRun` wrapper, which is rewritten with each Ghidra install: the keg-only `openjdk@N` the formula depends on, so the JDK the GUI uses, and never one a newer formula definition only promises; a `JAVA_HOME` already set wins, as in that wrapper, and one without `bin/java` is dropped with a warning) at every start, then execs the mise `rea` shim with `mcp`. If Ghidra is uninstalled after a registration, it warns on stderr and still starts REA for Hopper and the built-in providers. Nothing versioned is registered: the earlier registration carried `JAVA_HOME` for the dependency read once at setup time, and when Ghidra 12.2 moved from `openjdk@21` to `openjdk@25` (2026-10-22) it dangled until the next setup run, while `claude mcp get rea` still said Connected. `rea-mcp --print-env` shows the two values. The Hopper cask installs to REA's default launcher path, so nothing is set for it. REA's own `rea setup` is not used: it writes an `npx -y rea-agents@<exact version>` registration that goes stale, and `npx` resolves through npm's `min-release-age`. The stdio servers (mise, Serena, Scrapling, REA, SnippetsLab) go through one `register_mcp` helper that checks that an existing registration has the command, args and each environment line it would write (extra environment lines are not flagged) and warns with the re-register command when one is missing, so a prior `rea setup` registration or a moved launcher is never silently kept. The `reverse-engineer-anything` skill is REA's own bundled copy: `rea setup --skill-client shared --skill-client claude_code --skill --yes` installs it into `~/.agents/skills` and `~/.claude/skills` whenever the `rea` shim exists, Ghidra or not (both real directories, so `rea doctor` reports it `aligned`; a symlink the skills CLI left at `~/.claude/skills/reverse-engineer-anything` is removed first, because `rea setup` refuses to replace a link; `sysup` re-runs it after upgrading mise tools, so the skill always matches the installed server). It is not in `agents/claude-skills.txt`: the skills CLI's copy from the repo's `main` branch drifted from the installed release (it pinned `@latest` and described features the server lacked) and `rea doctor` called it stale. ## dotfiles

Two things happen here, in this order. Both are safe to repeat.

### mise dotfiles apply

`setup.sh` runs `mise dotfiles apply` from `$HOME` before the packages, and the `dotfiles` part of `mise bootstrap` then finds nothing left to do. `setup.sh` has already stopped by then when `~/.config/mise` is not the clone's `tilde/.config/mise` (see [setup.sh](#setupsh-wrapper)).

The apply makes what the 38 `[dotfiles]` entries in [`40-dotfiles.toml`](../tilde/.config/mise/conf.d/40-dotfiles.toml) declare. Every source is written `~/dotfiles/…`, which is why that link must be the clone.

- Each top-level file of `tilde/` becomes a symlink in `~` (e.g. `~/.zshrc`, `~/.gitconfig`), and each folder under `tilde/.config/` is linked individually into `~/.config/`. Each has its own entry. A new one needs an entry too, and `pnpm check` fails without it (`bin/lib/test-dotfiles`).
- Claude Code's global instructions are the rules in `tilde/.claude/rules/`. `~/.claude/rules` stays a real directory, so machine-local rules can sit next to them, and each tracked rule is linked into it. mise walks that folder, so a new rule needs no entry. Each skill in `tilde/.claude/skills/` and the status line script `statusline-command.sh` has its own entry. `~/.claude/CLAUDE.md` (rewritten by `codegraph install`), `~/.claude/settings.json` (rewritten by Claude Code and plugins) and `~/.claude.json` (auth and machine state) aren't tracked.
- `~/.ssh` and `~/.gnupg` are real directories, created if missing and set to `700`. Only the tracked `~/.ssh/config` and `~/.gnupg/gpg-agent.conf` are linked into them, so key files are never touched.
- `vscode/User` → `~/Library/Application Support/Code/User`. The repo is the source of truth, so keep VS Code's built-in Settings Sync off (its `vscode/**/sync/` cache and `vscode/**/profiles/` are gitignored).
- lazydocker's and rtk's configs, and Codex's `~/.codex/AGENTS.md`.
- Codex's `config.toml` is never linked, because setup's own `codex mcp add`, Hindsight and Codex itself write it, and MCP entries can carry tokens. It is a `merge = "missing"` entry: created at `0600` when missing, then each apply adds only the keys the live file lacks and keeps every value it has. The tracked file's comments are not copied, and a key you delete from the live file comes back on the next apply unless you delete it from `tilde/.codex/config.toml` too.
- Mole's `~/.config/mole/whitelist` and `whitelist_optimize`, each to the shared `mole/<name>`. Only the two files are linked because Mole writes `clean-list.txt` and `purge_paths` into the same folder. A Mac keeps its own list (`mole/<name>.local`, a full replacement, not merged) by repeating the entry in the gitignored `tilde/.config/mise/config.local.toml`, which replaces the tracked entry. See [docs/mole.md](../docs/mole.md#configuration).

lazygit's `state.yml` is machine-local and not linked.

A real file or folder where a link belongs stops the run: `mise dotfiles apply` names every such path and writes nothing. Move it aside, or adopt it with `mise dotfiles add <path>` (your file then replaces the tracked one, so check `git diff`), and run again. There is no prompt. `mise dotfiles apply --force` replaces the file with no backup, so no script here passes it. A link that points somewhere else is repointed without asking.

`mise dotfiles status` shows what is not in its declared state, and `mise dotfiles apply --dry-run` prints what an apply would do. Run both from `~`. A plain `mise bootstrap` run by hand applies the same entries as one of its steps. It does not run the extras script below.

### dotfiles-extras.sh

[`dotfiles-extras.sh`](dotfiles-extras.sh) does what `[dotfiles]` cannot express. `setup.sh` runs it after the `bootstrap` task succeeds, except on a `--dry-run` or when `dotfiles` is in the `--skip` list. It is not a mise `post-dotfiles` hook, because a hook also runs on every plain `mise dotfiles apply`, where nobody may be there to answer its prompts.

It puts `~/.local/bin` and `bin` and `sbin` under `$HOMEBREW_PREFIX` (default `/opt/homebrew`) on its PATH first, so the `bat`, `cot` and `code` checks below see the installed tools even when run outside a login shell. Then, in order:

- It runs `configure_git_identity`, which resets the terminal (`stty sane`, since an earlier step can leave it without echo) and then prompts for your git name/email and signing method and writes `~/.gitconfig.local` (never committed — see `tilde/.gitconfig`'s `[include]`). SSH signing means 1Password: it writes `gpg.ssh.program = /Applications/1Password.app/Contents/MacOS/op-ssh-sign` and asks for your public key; GPG asks for a key ID. The whole step is skipped if `~/.gitconfig.local` already exists. `DOTFILES_GIT_NAME`, `DOTFILES_GIT_EMAIL`, `DOTFILES_GIT_SIGN_METHOD` and `DOTFILES_GIT_SIGNINGKEY` pre-fill (and skip) their own prompts; without a name and email the file isn't written.
- It warns if `~/.ssh/github_personal.pub` — the public key that pins GitHub to your 1Password key — is missing.
- It links the `cot` and `code` command-line tools into `/usr/local/bin` if they're not already on PATH. A CLI whose app isn't installed is skipped with a warning, and a file already at that path that isn't the link is left alone with a warning. It asks for the administrator password only when a link has to be made and `/usr/local/bin` is missing or not writable.
- It hard-links the Firefox Developer Edition styles into its profile. A file there with different content is moved to `<name>.backup` first, or to `<name>.backup.<YYYYmmdd-HHMMSS>` when that already exists, so an earlier backup is never overwritten and a pull that changes a tracked file reaches Firefox on the next run. There is no prompt. Without a dev-edition profile it is skipped with a warning.
- It rebuilds bat's cache so the themes in `tilde/.config/bat/themes` load.

## macos

Sane macOS defaults, declared in [`20-macos.toml`](../tilde/.config/mise/conf.d/20-macos.toml) and applied with `set-defaults` only. `setup.sh` skips them. A plain `mise bootstrap` run by hand does apply them and runs both hooks. Based on [~/.macos](https://mths.be/macos) by @mathiasbynens, reviewed for macOS 27.

Nothing prompts. Set the computer name in `dotfiles-settings` (`macos.computer_name`, optionally `macos.local_hostname`) or run `set-defaults --computer-name "Name"` (with an optional `--local-hostname host`); the next `set-defaults` renames the Mac when the computer name or the local hostname differs from the Mac's. A local hostname alone, without a computer name, changes nothing. A name with no Latin letter or digit derives no local hostname, so the rename is skipped with a warning until you give one.

Higher-impact settings are per-machine choices, because the right answer varies per machine (a work laptop with its firewall or updates managed by MDM, a Mac that backs up with Time Machine):

- Settings in the "macOS (this Mac)" section of `dotfiles-settings`. They need sudo, and `set-defaults` asks for it only when the Mac differs. Every command it runs as root is taken from `/usr/bin`, `/bin`, `/usr/sbin`, `/sbin` or the firewall's system folder, never from elsewhere on your `PATH`, because macOS `sudo` keeps the caller's `PATH`. Turning one off later changes nothing on the Mac. Two are **on unless you switch them off**: `macos.firewall` (firewall and stealth mode) and `macos.disable_time_machine`. **With its default, `set-defaults` stops all Time Machine backups.** A fork, or any Mac that uses Time Machine, must run `dotfiles-settings set macos.disable_time_machine off` (or export `DOTFILES_MACOS_DISABLE_TIME_MACHINE=` in `~/.zsh.local`) before the first `set-defaults` or plain `mise bootstrap`. To skip it for one run only: `DOTFILES_MACOS_DISABLE_TIME_MACHINE= set-defaults`. The rest are off or empty unless you set them: `macos.hidpi` (HiDPI display modes, needs a restart), and the text settings `macos.computer_name` and `macos.local_hostname` (derived from the name when empty, and used only together with a computer name). The `set-defaults` flags `--firewall`, `--disable-time-machine` and `--hidpi` turn a switch on for one run even when its setting is off, and `--computer-name` and `--local-hostname` replace the setting for one run (`--local-hostname` only together with a computer name).
- Tables in the git-ignored `tilde/.config/mise/config.local.toml`, which outranks the fragment: disabling the "downloaded from the internet" confirmation and skipping disk image verification (**both weaken security**), and custom Dock auto-hide timing. The fragment's header has the tables to copy.

Four groups the old script asked about are on unless you switch them off in the same section: `macos.screenshots` (save to the Desktop as PNG named "Shot", no window shadow, pointer shown), `macos.time_machine_new_disks` (stop Time Machine offering new disks for backup), `macos.textedit` (plain text and UTF-8) and `macos.software_update` (daily check, background download, security and system data installs). Switch a group off on a Mac whose updates or backups are managed by MDM; `set-defaults` then leaves it as it is. Each setting is the variable `DOTFILES_MACOS_<NAME>`, stored in the git-ignored override file, so an export in `~/.zsh.local` works too (empty means off for a group). The old script's two answer-everything variables are gone.

Always applied, from the fragment or by the extras script (`pmset`, the file flags, the `$HOME` path):

- Keyboard: very fast key repeat (1 / 10, beyond System Settings' fastest) with press-and-hold off; system-wide autocorrect and smart punctuation off.
- Trackpad: no swipe between pages (natural scrolling is left alone).
- Dock: auto-hide, size 38, no recent apps, "suck" minimize into the app icon, no bouncing; Mission Control groups windows by app.
- Finder: hidden files, extensions, path and status bars, list view, drive icons and Stacks on the desktop, new windows open in your home folder; `~/Library` and `/Volumes` unhidden; no `.DS_Store` files on network/USB drives.
- All hot corners set to no action; ⌘Space freed from Spotlight (for Raycast).
- Language and region: en-US, USD, inches, °F.
- Energy (`pmset`): lid wake on, disk sleep 10 min, no wake for network access, hibernation mode 3.
- Crash-reporter dialog off; Terminal.app uses UTF-8 and Secure Keyboard Entry.

Safari isn't configured — it's sandboxed, so its preferences can't be set from a script; use Safari → Settings.

What changed from the old script:

- mise never deletes a preference. Removing a line from the fragment leaves the value in place; run `defaults delete <domain> <key>` to return to the macOS default. The old script deleted the Dock timing keys when you declined them.
- mise never uses sudo. The settings that need it (`pmset`, unhiding `/Volumes`, the opt-ins) are in `setup/macos-extras.sh`, which asks for sudo only when a value differs.
- mise doesn't restart apps. The extras script force-quits Finder, Dock, Activity Monitor, Notification Center, SystemUIServer and Terminal when the apply wrote a preference (always under `set-defaults`), and spares Terminal when it is the terminal you ran it from. Key repeat needs a logout to take effect.
- TextEdit, Preview and Help Viewer are sandboxed, so mise can't read their preferences back; the extras script writes them and `status` doesn't list them. A terminal without Full Disk Access is refused that write: the script prints a warning for the preference and carries on. Finder's new-window path holds `$HOME` and is written there too, as are the four switchable groups, since mise applies every preference the fragment declares.
- `mise bootstrap macos defaults status` lists every declared preference as set, differs or unset. `pnpm check` warns about drift and fails only on a type mismatch.

## dash

Optional, interactive: adds Dash docsets generated from local folders of **HTML** documentation (Dash's Docset Generator doesn't read Markdown). Docsets you download inside Dash need nothing from this — Dash syncs that list itself.

Prerequisite: in Dash → Settings → General, set the sync folder to the repo's `dash/` folder and tick all four "What to sync" options (General settings, View options, Docsets/search profiles/keywords, Bookmarks and web searches) — but not "Sync Snippets", which would move Dash's snippet database into the repo.

Dash writes absolute paths and has no variable expansion, so folder docsets can't be committed portably — quit Dash, run `setup/dash.sh` (or `setup.sh --dash`) and enter the folders to index, then build them in Dash → Settings → Downloads → Docset Generator. Also usable non-interactively: `setup/dash.sh add <folder> [name] [keyword]`.
